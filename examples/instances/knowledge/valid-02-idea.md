Полку прочитанного стоит показывать карточками с обложками (теневое свойство `cover_file`
уже даёт Bases нужные данные) — проверить на трёх книгах, потом решить, не мешают ли
крупные карточки быстрому просмотру списка.

Корректный экземпляр `knowledge` (батч 4, D3). Что демонстрирует:

- **пограничный случай из карточки §3**: «идея новой функции» — это `knowledge`
  (вид «Идея» категорией); «работы по её внедрению, которые начаты» — это `project`.
  Знание отвечает «что я думаю», проект — «что я делаю»;
- `related_to` → **проект**: пара knowledge↔project допустима (карточка `project` §5
  перечисляет knowledge среди целей; на уровне типа отношения `related_to` в MVP
  допущены четыре предметных типа ядра — DL-234);
- значение `title` с двоеточием — **в кавычках** (конвенция батча 1);
- свойство `source` не заполнено — оно необязательное: идея родилась в разговоре,
  источника-документа нет (пустое `source` законно, `0..1`);
- `tags` отсутствуют — свободные метки необязательны;
- тело — развёрнутая формулировка мысли (не пустое: `knowledge.body.not_empty`).

- Схема: `schema/entities/knowledge.schema.json`.
