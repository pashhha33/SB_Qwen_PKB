# 05. Перечисления и справочники

> [!info] Статус документа
> Нормативный. Основание — [[../adr/ADR-011-enumerations-dates-lifecycle|ADR-011]].
> Этот файл — **единственный источник** для всех закрытых перечислений модели. Код плагина сверяется
> с ним тестом (мера M5 ADR-011).

## 1. Два механизма для двух задач

| Механизм | Что это | Когда применять | Где живёт |
|---|---|---|---|
| **Перечисление** (`allowed_values`) | Закрытый список значений в определении свойства | Значений мало, они стабильны, меняются только вместе с метамоделью | Этот документ + определение свойства |
| **Категория фасета** | Открытый справочник, который пополняет пользователь | Значений много, список растёт, нужна иерархия или русские подписи | Объекты `category` в хранилище |

**Правило выбора** (из ADR-006): значений меньше десятка и они технически стабильны → перечисление;
значений много и их пополняет пользователь → категория фасета.

## 2. Стиль значений

| Что | Норма | Пример |
|---|---|---|
| Значение в данных | английский `snake_case` | `strict`, `in_progress` |
| Проверка формата | `^[a-z][a-z0-9_]*$` | правило `enum.value.format`, `error` |
| Подпись для интерфейса | русский текст, хранится отдельно | «Строгая», «В работе» |

**Запрещено:** смешение кириллицы и латиницы в одном значении, пробелы, регистрозависимые различия
как единственный способ отличить два значения.

> [!warning] Почему это важно
> В исходных черновиках уже были две опечатки, невидимые глазу: `CHARACTЕR` (кириллическая «Е»)
> и `полиaрхическая` (латинская «a»). Для программы это **другие значения**. Английский `snake_case`
> делает такую ошибку видимой сразу, а автоматическая проверка (DL-020) ловит её до записи.

## 3. Реестр закрытых перечислений

### 3.1. Типы значений (`value_type`)

Используется в: `property.value_type`. Набор **закрыт**, изменение — ломающее MAJOR.

| Значение | Подпись | Что хранит |
|---|---|---|
| `text` | Текст | Строка |
| `number` | Число | Целое или дробное |
| `date` | Дата | `YYYY-MM-DD`, локальная; допускаются частичные значения |
| `datetime` | Дата и время | `YYYY-MM-DDTHH:mm`, локальное |
| `boolean` | Логическое | `true` / `false` |
| `object_reference` | Ссылка на объект | Ссылка на объект метамодели или данных |
| `media_reference` | Ссылка на медиа | Ссылка на объект `media` или на файл вложения |

### 3.2. Кардинальность (`cardinality`)

Используется в: `property.cardinality`, `relation_type.subject_to_object`,
`relation_type.object_to_subject`, `facet.assignment_cardinality`.

| Значение | Подпись | Смысл |
|---|---|---|
| `1` | Ровно одно | Обязательно, одно значение |
| `0..1` | Ноль или одно | Необязательно, не более одного |
| `0..N` | Ноль или много | Необязательно, сколько угодно |
| `1..N` | Одно или много | Обязательно, сколько угодно |

Согласованность с `required`: `1` и `1..N` → `required: true`; `0..1` и `0..N` → `required: false`.
Правило `property.required.cardinality_consistency`, уровень `error`.

### 3.3. Область применения свойства (`scope`)

Используется в: `property.scope`.

| Значение | Подпись | Смысл |
|---|---|---|
| `universal` | Универсальное | Применимо ко всем типам объектов |
| `family` | Семейство | Применимо к группе типов-наследников |
| `specific` | Специфичное | Применимо к одному типу |

### 3.4. Жизненный цикл (`lifecycle`)

Используется в: `property.lifecycle`, `object_type.lifecycle`. Поведение описано в ADR-011, часть 5.

| Значение | Подпись | Что делает плагин |
|---|---|---|
| `experimental` | Экспериментальное | Принимается, при валидации — `info` |
| `standard` | Стандартное | Обычное поведение. **По умолчанию** |
| `deprecated` | Устаревшее | `warning`; команды создания не предлагают; обязательно `superseded_by` |
| `archived` | Архивное | Скрыто из форм и списков; значения сохраняются; валидация молчит |

### 3.5. Режим иерархии (`hierarchy_mode`)

Используется в: `facet.hierarchy_mode`, `taxonomy.hierarchy_mode` (значение по умолчанию).

| Значение | Подпись | Смысл |
|---|---|---|
| `strict` | Строгая | У категории не более одного родителя. Дерево |
| `polyhierarchical` | Полиерархическая | У категории может быть несколько родителей. Сеть |

> [!note] Происхождение значения
> В исходной спецификации было написано `полиaрхическая` — с латинской «a» вместо кириллической.
> Переход на английский `snake_case` снимает такие опечатки как класс проблем.

### 3.6. Направление связи (`direction`)

Используется в: `relation_type.direction`.

| Значение | Подпись | Смысл | Хранение |
|---|---|---|---|
| `directed` | Направленное | Стороны неравноправны: субъект и объект | Как обычно |
| `symmetric` | Симметричное | Читается одинаково в обе стороны | Один раз; обратная сторона вычисляется |

У симметричного типа `forward_label` и `reverse_label` обязаны совпадать
(правило `relation_type.symmetric.labels_equal`, `warning`).

### 3.7. Правило уникальности (`uniqueness_rule`)

Используется в: `relation_type.uniqueness_rule`. По умолчанию `triple`.

| Значение | Подпись | Что считается дублем |
|---|---|---|
| `pair` | По паре | Пара «субъект — объект»: между ними вообще не может быть двух связей |
| `triple` | По тройке | Тройка «субъект — тип отношения — объект». **По умолчанию** |
| `none` | Без проверки | Ограничений нет |

### 3.8. Способ хранения связи (`link_mode`)

Используется в: `property.link_mode`. Обязательно для свойств типа `object_reference`.

| Значение | Подпись | Где хранится значение |
|---|---|---|
| `direct` | Прямая ссылка | В поле самого объекта, wikilink |
| `reified` | Реифицированная связь | Объект `relation` в `.sb/relations/relations.jsonl` |

| Значение | Подпись | Происхождение |
|---|---|---|
| `cover` | Обложка | v1.0 §12 |
| `banner` | Баннер | v1.0 §12 |
| `logo` | Логотип | v1.0 §12 |
| `portrait` | Портрет | v1.0 §12 |
| `avatar` | Аватар | v1.0 §12 |
| `preview` | Превью | v1.0 §12 |
| `background` | Фон | v1.0 §12 |
| `other` | Прочее | v1.0 §12 |
| `illustration` | Иллюстрация | DL-142 |
| `photo` | Фотография | DL-142 |
| `screenshot` | Снимок экрана | DL-142 |
| `diagram` | Схема, диаграмма | DL-142 |
| `attachment` | Приложение к заметке | DL-142 |

**Кратность: мультивыбор (DL-142).** Свойство `media.role` имеет `cardinality: 0..N`: одно и то же
изображение законно бывает и обложкой книги, и иллюстрацией к главе, и портретом автора. Требование
пользователя от 2026-10-22: «роль обёртки должна быть мульти выбором, если она возьмёт на себя не одну
роль». Следствие для свойств: `property.media_roles` проверяется правилом `media.roles_allowed`
по **пересечению** списков — хотя бы одна роль объекта должна входить в `media_roles` свойства.

Правило из спецификации сохраняется: **роль не кодируется в имени файла**.

### 3.17. Перечисления данных (экземплярные)

Первые три перечисления описывали **метамодель**. Ниже — перечисления, значения которых
хранятся в заметках пользователя. Правила те же: английский `snake_case`, русская подпись,
закрытый список (ADR-003, ADR-011).

#### 3.17.1. `book_format` — формат книги (DL-127)

Используется в: свойство `format` типа `book`. **Обязательное** для книги.
Является **триггером** условных свойств (`applies_when`, DL-128).

| Значение | Подпись | Смысл | Включаемые свойства |
|---|---|---|---|
| `file` | Файл | Книга как файл в хранилище или на диске | `file_path`, `file_format` |
| `card` | Карточка | Бумажная карточка / картотечная запись | `card_series`, `card_count` |
| `web_novel` | Веб-новела | Сериал, публикуемый главами на площадке | `platform`, `publication_status`, `release_cadence`, `last_chapter_on` |
| `print` | Печатная | Бумажное издание | — (см. сноску) |
| `audio` | Аудио | Аудиокнига | `audio_duration`, `narrator` |

**Статус: ЗАКРЫТО** решением пользователя от 2026-10-22 (DL-121, вариант B). Значение
`online_literature` («сетевая литература») **не введено**: это надмножество веб-новелы, отдельный
набор свойств ей не требуется. Различать произведения внутри веб-новел можно категорией фасета
`genre` или свободной меткой (глоссарий: *надмножество*).

> [!note] Сноска к строке `print` (исправление батча 2, DL-228)
> Ранее в «включаемых свойствах» строки `print` значились `pages`, `isbn`, `publisher` —
> это противоречило DL-122 (утверждено **10** условных свойств, и этих трёх среди них нет):
> по карточке `book` §4 они являются **базовыми** свойствами (необязательными у любого формата).
> Условных свойств у `print` нет.

**Почему `print` и `audio` оставлены, хотя есть `media_kind`:** `format` отвечает на вопрос
«в каком виде я это читаю/веду», а `media_kind` — «что за файл лежит в хранилище». Аудиокнига
может быть заведена как `book` с `format: audio` (учёт прослушанного) и при этом иметь связанный
объект `media` с `media_kind: audio` (сам файл). Это разные сведения, они не дублируют друг друга.

#### 3.17.5. `person_role` — род занятий человека (DL-137, DL-138)

Используется в: свойство `role` типа `person`. **Множественный выбор**, свойство обязательно
(`cardinality: 1..N`, DL-156).
Является **триггером** условных свойств: операция `includes_any`
(см. [[../04-attributes#11.3. Что может быть триггером|атрибуты §11.3]]).

Список собран по образцам вики-инфобоксов и свойствам Wikidata (см.
`docs/metamodel/research/person-role-properties.md`); значения с одинаковым набором свойств
объединены в **группы** — свойство объявляется один раз на группу (правило М7), а не по разу
на профессию.

| Группа | Значения | Подписи | Включаемые свойства |
|---|---|---|---|
| **Литература и текст** | `author`, `novelist`, `poet`, `screenwriter`, `translator`, `editor`, `blogger` | Автор, Прозаик, Поэт, Сценарист, Переводчик, Редактор, Блогер | `writing_genres`, `writing_languages`, `published_works` (сноска: `pen_name` — базовое свойство, DL-151/228) |

| **Исполнительские искусства** | `actor`, `director`, `musician`, `composer`, `singer`, `dancer`, `voice_actor` | Актёр, Режиссёр, Музыкант, Композитор, Вокалист, Танцовщик, Актёр озвучивания | `instruments`, `performance_genres`, `ensembles` |
| **Спорт** | `athlete`, `coach`, `esport_player` | Спортсмен, Тренер, Киберспортсмен | `sport`, `sport_position`, `sport_teams` |
| **Наука и образование** | `scientist`, `academic`, `teacher`, `engineer`, `inventor` | Учёный, Преподаватель вуза, Педагог, Инженер, Изобретатель | `academic_degree`, `academic_institutions`, `doctoral_advisor`, `thesis_title` |
| **Медицина** | `physician` | Врач | `medical_specialty`, `medical_institution` |
| **IT и разработка** | `programmer`, `game_developer`, `data_scientist` | Программист, Геймдевелопер, Дата-сайентист | `programming_languages`, `software_projects` |
| **Бизнес** | `entrepreneur`, `executive`, `investor` | Предприниматель, Руководитель, Инвестор | `business_positions` |
| **Служба и государство** | `politician`, `military`, `civil_servant`, `diplomat`, `jurist` | Политик, Военный, Госслужащий, Дипломат, Юрист | `office_held`, `military_rank`, `conflicts` |
| **Сквозные** | — | — | `known_for`, `field_of_work`, `active_years` — включаются при любом значении из нескольких групп |

способ заполнить обязательное поле, не выдумывая профессию.

> строк таблицы даёт **39 групповых + 1 служебное = 40**. Состав значений утверждён пользователем
> «как есть, без сокращений» (DL-157) и **не менялся**; ошибка была только в счётчике. Исправлено
> здесь, в `rules.md`, карточке `person` и исследовании `person-role-properties.md`; записи
> DL-137/DL-157 как хроника не переписываются. Машиночитаемый эталон состава —
> `schema/entities/person.schema.json` (`$defs.person_role_value`, 40 значений).

**Статус: ЗАКРЫТО** решением пользователя от 2026-10-22 (ответ A, DL-157). Значение добавляется
командой `create-enum-value` (этап 2) или правкой метамодели; у пользовательского значения просто
не будет условных свойств, и это нормальное состояние, а не ошибка.
**Уточнение DL-224 (батч 2):** пока значение не добавлено в перечисление, оно в данных —
ошибка (`person.role.enum`, error; перечисление зашито в `schema/entities/person.schema.json`).
Info-правило `person.role.suggested` относится к значениям, которые **есть** в перечислении,
но не входят ни в одну группу (`other_occupation` и будущие пользовательские) — они допустимы
и просто не включают условных свойств.

**Почему перечисление, а не категория фасета «Род занятий»** (так было в первой версии карточки
`person`): от значения зависит **состав полей**, а это признак перечисления (правило выбора —
[[../04-attributes#5. Перечисление или словарь — правило выбора|атрибуты §5]], DL-120
для `book_format`). Фасет «Род занятий» в MVP **не вводится**: два механизма для одного смысла
дали бы рассинхрон. Если пользователю понадобится свободная классификация людей, это решается
категориями другого фасета или метками.

#### 3.17.6. `media_creation_method` — способ создания медиа (DL-141)

Используется в: свойство `creation_method` типа `media`. **Множественный выбор**
(`cardinality: 0..N`): коллаж из фотографии, обработанной нейросетью, — это законно три способа
сразу. Триггер условных свойств, операция `includes_any`.

| Значение | Подпись | Включаемые свойства |
|---|---|---|
| `photo` | Фотография | `captured_at`, `capture_device`, `capture_location` |
| `drawing` | Рисунок, живопись | `art_tool`, `art_medium` |
| `digital_art` | Цифровая графика | `software_used` |
| `collage` | Коллаж, компиляция | `source_materials` |
| `ai_generated` | Генерация ИИ | `ai_model`, `ai_prompt`, `ai_negative_prompt`, `ai_seed`, `ai_sampler`, `ai_steps`, `ai_base_image`, `ai_generated_on` |
| `scan` | Сканирование | `scan_source`, `scan_dpi` |
| `screenshot` | Снимок экрана | `screenshot_of`, `captured_at` |
| `render` | 3D-рендер | `software_used`, `render_engine` |

**Граница с `media_kind`** (по образцу границы `format` / `media_kind`, DL-135): `media_kind` —
«что за файл лежит в хранилище» (изображение, аудио, видео), `creation_method` — «как он появился».
Скриншот — это `media_kind: image` и `creation_method: screenshot`.

**Граница с `media.role`:** роль отвечает на вопрос «зачем он здесь» (обложка, портрет, иллюстрация),
способ создания — «как он сделан». Одно фото может быть и портретом, и обложкой; способ создания
у него один.

**Статус: ЗАКРЫТО** решением пользователя от 2026-10-22 (ответ A, DL-155): все 8 значений,
включая `render` и `scan`; 8 полей `ai_*` подтверждены.
