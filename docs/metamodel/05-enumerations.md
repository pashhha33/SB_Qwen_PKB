# 05. Перечисления и справочники

> [!info] Статус документа
> Нормативный. Основание — [[../adr/ADR-011-enumerations-dates-lifecycle|ADR-011]].
> Этот файл — **единственный источник** для всех закрытых перечислений модели. Код плагина сверяется
> с ним тестом (мера M5 ADR-011).

## 1. Два механизма для двух задач

| Механизм | Что это | Когда применять | Где живёт |
|---|---|---|---|
| **Перечисление** (`allowed_values`) | Закрытый список значений в определении свойства | Значений мало, они стабильны, меняются только вместе с метамоделью | Этот документ + определение свойства |
| **Категория фасета** | Открытый справочник, который пополняет пользователь | Значений много, список растёт, нужна иерархия или русские подписи | Объекты `category` в хранилище |

**Правило выбора** (из ADR-006): значений меньше десятка и они технически стабильны → перечисление;
значений много и их пополняет пользователь → категория фасета.

## 2. Стиль значений

| Что | Норма | Пример |
|---|---|---|
| Значение в данных | английский `snake_case` | `strict`, `in_progress` |
| Проверка формата | `^[a-z][a-z0-9_]*$` | правило `enum.value.format`, `error` |
| Подпись для интерфейса | русский текст, хранится отдельно | «Строгая», «В работе» |

**Запрещено:** смешение кириллицы и латиницы в одном значении, пробелы, регистрозависимые различия
как единственный способ отличить два значения.

> [!warning] Почему это важно
> В исходных черновиках уже были две опечатки, невидимые глазу: `CHARACTЕR` (кириллическая «Е»)
> и `полиaрхическая` (латинская «a»). Для программы это **другие значения**. Английский `snake_case`
> делает такую ошибку видимой сразу, а автоматическая проверка (DL-020) ловит её до записи.

## 3. Реестр закрытых перечислений

### 3.1. Типы значений (`value_type`)

Используется в: `property.value_type`. Набор **закрыт**, изменение — ломающее MAJOR.

| Значение | Подпись | Что хранит |
|---|---|---|
| `text` | Текст | Строка |
| `number` | Число | Целое или дробное |
| `date` | Дата | `YYYY-MM-DD`, локальная; допускаются частичные значения |
| `datetime` | Дата и время | `YYYY-MM-DDTHH:mm`, локальное |
| `boolean` | Логическое | `true` / `false` |
| `object_reference` | Ссылка на объект | Ссылка на объект метамодели или данных |
| `media_reference` | Ссылка на медиа | Ссылка на объект `media` или на файл вложения |

### 3.2. Кардинальность (`cardinality`)

Используется в: `property.cardinality`, `relation_type.subject_to_object`,
`relation_type.object_to_subject`, `facet.assignment_cardinality`.

| Значение | Подпись | Смысл |
|---|---|---|
| `1` | Ровно одно | Обязательно, одно значение |
| `0..1` | Ноль или одно | Необязательно, не более одного |
| `0..N` | Ноль или много | Необязательно, сколько угодно |
| `1..N` | Одно или много | Обязательно, сколько угодно |

Согласованность с `required`: `1` и `1..N` → `required: true`; `0..1` и `0..N` → `required: false`.
Правило `property.required.cardinality_consistency`, уровень `error`.

### 3.3. Область применения свойства (`scope`)

Используется в: `property.scope`.

| Значение | Подпись | Смысл |
|---|---|---|
| `universal` | Универсальное | Применимо ко всем типам объектов |
| `family` | Семейство | Применимо к группе типов-наследников |
| `specific` | Специфичное | Применимо к одному типу |

### 3.4. Жизненный цикл (`lifecycle`)

Используется в: `property.lifecycle`, `object_type.lifecycle`. Поведение описано в ADR-011, часть 5.

| Значение | Подпись | Что делает плагин |
|---|---|---|
| `experimental` | Экспериментальное | Принимается, при валидации — `info` |
| `standard` | Стандартное | Обычное поведение. **По умолчанию** |
| `deprecated` | Устаревшее | `warning`; команды создания не предлагают; обязательно `superseded_by` |
| `archived` | Архивное | Скрыто из форм и списков; значения сохраняются; валидация молчит |

### 3.5. Режим иерархии (`hierarchy_mode`)

Используется в: `facet.hierarchy_mode`, `taxonomy.hierarchy_mode` (значение по умолчанию).

| Значение | Подпись | Смысл |
|---|---|---|
| `strict` | Строгая | У категории не более одного родителя. Дерево |
| `polyhierarchical` | Полиерархическая | У категории может быть несколько родителей. Сеть |

> [!note] Происхождение значения
> В исходной спецификации было написано `полиaрхическая` — с латинской «a» вместо кириллической.
> Переход на английский `snake_case` снимает такие опечатки как класс проблем.

### 3.6. Направление связи (`direction`)

Используется в: `relation_type.direction`.

| Значение | Подпись | Смысл | Хранение |
|---|---|---|---|
| `directed` | Направленное | Стороны неравноправны: субъект и объект | Как обычно |
| `symmetric` | Симметричное | Читается одинаково в обе стороны | Один раз; обратная сторона вычисляется |

У симметричного типа `forward_label` и `reverse_label` обязаны совпадать
(правило `relation_type.symmetric.labels_equal`, `warning`).

### 3.7. Правило уникальности (`uniqueness_rule`)

Используется в: `relation_type.uniqueness_rule`. По умолчанию `triple`.

| Значение | Подпись | Что считается дублем |
|---|---|---|
| `pair` | По паре | Пара «субъект — объект»: между ними вообще не может быть двух связей |
| `triple` | По тройке | Тройка «субъект — тип отношения — объект». **По умолчанию** |
| `none` | Без проверки | Ограничений нет |

### 3.8. Способ хранения связи (`link_mode`)

Используется в: `property.link_mode`. Обязательно для свойств типа `object_reference`.

| Значение | Подпись | Где хранится значение |
|---|---|---|
| `direct` | Прямая ссылка | В поле самого объекта, wikilink |
| `reified` | Реифицированная связь | Объект `relation` в `.sb/relations/relations.jsonl` |

### 3.9. Вид медиа (`media_kind`)

Используется в: `media.media_kind`, `property.media_kinds`.

| Значение | Подпись | Значок в контроле |
|---|---|---|
| `image` | Изображение | миниатюра |
| `audio` | Аудио | значок ноты |
| `video` | Видео | значок плёнки |
| `document` | Документ | значок листа |
| `other` | Прочее | значок файла |

### 3.10. Роль медиа (`media_role`)

Используется в: `media.role`, `property.media_roles`. Роли сохранены из спецификации v1.0 §12.

| Значение | Подпись |
|---|---|
| `cover` | Обложка |
| `banner` | Баннер |
| `logo` | Логотип |
| `portrait` | Портрет |
| `avatar` | Аватар |
| `preview` | Превью |
| `background` | Фон |
| `other` | Прочее |

Правило из спецификации сохраняется: **роль не кодируется в имени файла**.

### 3.11. Цель ссылки на медиа (`media_target`)

Используется в: `property.media_target`. Обязательно для свойств типа `media_reference`.

| Значение | Подпись | Что выбирается |
|---|---|---|
| `object` | Объект медиа | Только объекты типа `media` |
| `file` | Файл | Только файлы вложений |
| `both` | Объект или файл | И то и другое |

### 3.12. Способ показа медиа (`media_display`) и размер миниатюры (`media_thumbnail_size`)

| Перечисление | Значения | Подписи |
|---|---|---|
| `media_display` | `gallery`, `list` | Галерея карточек, Список |
| `media_thumbnail_size` | `small`, `medium`, `large` | Мелкий, Средний, Крупный |

### 3.13. Механизм представления (`mechanism`)

Используется в: `view.mechanism`. **Предварительный список**, утверждается на шаге 8.

| Значение | Подпись | Статус |
|---|---|---|
| `base` | Obsidian Bases | подтверждённая интеграция |
| `plugin_view` | Собственное представление плагина | MVP |
| `dataview` | Dataview | под вопросом, C-10 |
| `dataviewjs` | DataviewJS | под вопросом, C-10 |

### 3.14. Триггер и механизм автоматизации

Используется в: `automation.trigger`, `automation.mechanism`. **Предварительный список**, шаг 8.

| Перечисление | Значения | Статус |
|---|---|---|
| `trigger` | `manual`, `on_create`, `on_edit`, `on_schedule` | `manual` — MVP, остальные этап 2 |
| `mechanism` | `plugin_command`, `templater`, `quickadd` | `quickadd` под вопросом, C-11 |

### 3.15. Статусы документов проекта

Используется в: frontmatter всех документов `docs/`. Не является частью модели данных, но зафиксирован
здесь для полноты.

| Значение | Подпись | Смысл |
|---|---|---|
| `draft` | Черновик | Ещё не подтверждён |
| `proposed` | Предложено | Ждёт решения |
| `accepted` | Принято | Действует |
| `actual` | Действующий | Текущая рабочая версия |
| `deprecated` | Устарело | Не использовать, но пока работает |
| `superseded` | Заменено | Есть новый документ, ссылка в `superseded_by` |

### 3.16. Статусы типов в реестре

Используется в: `docs/metamodel/02-entities.md`. Не хранится в данных.

| Значение | Подпись | Смысл |
|---|---|---|
| `core` | Ядро | Описывается детально в первом проходе |
| `core_abstract` | Абстрактный родитель ядра | Минимальная карточка |
| `phase2` | Этап 2 | В реестре, без детальной карточки |
| `deferred` | Отложен | Обозначен логически, не реализуется |
| `to_category` | Переквалифицирован в категорию | Не является типом |
| `needs_decision` | Требуется решение | Тесты не дали однозначного ответа |
| `out_of_scope` | Вне области | Не входит в модель |

## 5. Правила валидации перечислений

| ID правила | Формулировка | Уровень |
|---|---|---|
| `enum.value.format` | Значение соответствует `^[a-z][a-z0-9_]*$` | error |
| `enum.value.in_set` | Значение входит в реестр этого документа | error |
| `enum.value.no_mixed_script` | В значении нет символов кириллицы | error |
| `property.allowed_values.format` | Все значения в `allowed_values` свойства соответствуют `enum.value.format` | error |
| `property.allowed_values.unique` | В `allowed_values` нет повторов | error |
