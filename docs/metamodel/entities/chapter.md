# Тип объекта `chapter` — глава

> **Родитель:** `docs/metamodel/02-entities.md` (v0.3.0)
> **Дата:** 2026-10-22 · **Статус:** предложен → утверждён пользователем (DL-124)
> **Группа:** ядро · **Префикс:** `CHP` · **`abstract`:** нет · **`lifecycle`:** `standard`
> **Репозиторий:** https://github.com/pashhha33/SB_Qwen_PKB

**`label`:** Глава · **`label_plural`:** Главы
**`description`:** «Отдельная часть произведения (глава, пролог, эпилог,
приложение). Имеет порядковый номер внутри произведения, собственное название
(может отсутствовать) и навигацию по соседним частям.»

---

## 1. Почему это отдельный тип, а не заметка-раздел

| Проверка | Ответ |
| --- | --- |
| У главы есть **собственные атрибуты**? | Да: номер, название, дата публикации (для веб-сериалов), статус черновика |
| Глава участвует в **связях** как самостоятельный узел? | Да: входит в произведение, может содержать иллюстрации и упоминания персонажей |
| По главам нужен **поиск и навигация**? | Да — это прямое требование пользователя (кнопки «предыдущая / следующая») |
| Хватит ли **заголовка `##` внутри книги**? | Нет: заголовок нельзя связать отношением и нельзя включить в поиск как объект |

Вывод: отдельный тип. Глава — **полноценный объект** со своим `id` и файлом.

---

## 2. Системные атрибуты

Полный набор из 8 (ADR-006). Особенность — `title`:

| Атрибут | Особенность для `chapter` |
| --- | --- |
| `id` | ULID, имя файла `CHP-{ULID}.md` |
| `type` | `chapter` |
| `title` | название главы; **если название не задано** — «Глава {N}» (см. §5) |
| `aliases` | `[title]` по умолчанию; при пустом названии — `["Глава 7", "7"]` |
| `created_at` / `updated_at` | стандартно |
| `categories` | обычно пусты; жанр главы наследуется от произведения и **не дублируется** |
| `tags` | свободные метки |

## 3. Свойства

| # | `key` | `value_type` | `required` | `cardinality` | `label` | Настройки |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `chapter_number` | `number` | **да, условно** (не нужен при `is_front_matter: true` — DL-230) | `1` (при `is_front_matter: true` — `0..1`) | Номер | `display.renderer: plain` (прежнее `precision: 1` — ненормативно: §12 `04-attributes` не определяет `precision`, DL-237) |
| 2 | `chapter_title` | `text` | нет | `0..1` | Название главы | — |
| 3 | `is_front_matter` | `boolean` | нет | `0..1` | Вне нумерации | для пролога/эпилога/приложения |
| 4 | `published_on` | `date` | нет | `0..1` | Дата публикации | для веб-сериалов |
| 5 | `word_count` | `number` | нет | `0..1` | Объём (слов) | — |
| 6 | `draft_status` | `text` | нет | `0..1` | Статус черновика | перечисление из 4 значений — реестр `05-enumerations` §3.17.11 (DL-231) |

*(Кардинальности приведены к закрытому словарю ADR-006 — `1`/`0..1` вместо `single`; обозначение устарело в батче 3.)*

**Почему `chapter_number` — число, а не текст:**

- по нему **сортируются** соседние главы (кнопки навигации);
- его можно проверить на **уникальность внутри произведения** (правило `chapter.contains.required`);
- дробное значение (`7.5`) позволяет вставить интерлюдию, не перенумеровывая хвост.

`chapter_title` отделён от `title` намеренно: `title` — системный атрибут и
никогда не бывает пустым (при пустом названии он равен «Глава {N}»), а
`chapter_title` хранит **исходное намерение автора** — пусто значит «названия нет».

## 4. Связи

| Свойство | Тип отношения | `link_mode` | `origin_property` | Кардинальность |
| --- | --- | --- | --- | --- |
| `part_of_work` | **`contains`** (обратная сторона) | `reified` | `part_of_work` | `0..1` — **фактически обязательна** (`chapter.contains.required`) |

Локальные свойства связи: `order` (= `chapter_number`, дублируется для
сортировки без чтения заметки) и `role` (`chapter` / `prologue` / `epilogue` /
`interlude` / `appendix`).

Хранится связь **в `.sb/relations/relations.jsonl`** как запись `contains`
(ADR-010, DL-125). В frontmatter главы — ничего, кроме системных атрибутов.

Дополнительно (этап 2): `depicts` → `person`, `mentions` → объекты.

## 5. Правило наименования (требование пользователя)

При создании главы запрашивается, по порядку:

| Шаг | Запрос | Обязателен? | Если пропустить |
| --- | --- | --- | --- |
| 1 | **К какому произведению относится?** | **да** | создание отменяется (правило **`chapter.contains.required`**) |
| 2 | **Номер главы** | **да** | предлагается «максимальный существующий + 1» |
| 3 | **Название главы** | нет | `title` = «Глава {N}»; `chapter_title` остаётся пустым |

Формат заголовка при пропуске названия: **`Глава {N}`** — без точки, с обычным
пробелом, номер арабскими цифрами (`Глава 7`). Для дробных: `Глава 7.5`.
Для частей вне нумерации (`is_front_matter = true`) — по роли:
«Пролог», «Эпилог», «Приложение».

**Инвариант (И7, новый):** если `chapter_title` пуст, то
`title == "Глава " + chapter_number`. Проверка — правило **`chapter.title.fallback`**.
Если пользователь позже задаст название, `title` обновляется вместе с
`aliases[0]` (инвариант И1).

## 6. Навигация по главам (требование пользователя)

В заметке главы отображается **блок навигации** с тремя кнопками:

```
┌───────────────────────────────────────────────────────────┐
│  ◀ Глава 6   │   ↑ Книга: «Название»   │   Глава 8 ▶      │
└───────────────────────────────────────────────────────────┘
```

В исходнике заметки блок выглядит так:

````text
```sb-chapter-nav
```
````

**Правила (Н1–Н8):**

| № | Правило |
| --- | --- |
| **Н1** | Соседние главы определяются по `contains.order` (или `chapter_number`) **внутри одного произведения**: предыдущая — наибольшее значение меньше текущего, следующая — наименьшее больше текущего |
| **Н2** | Глава вне нумерации (`is_front_matter`) в порядке **не участвует**; пролог показывается перед главой 1, эпилог — после последней |
| **Н3** | Если соседней главы **нет** — кнопка не исчезает, а меняет действие: **«Создать главу {N}»** |
| **Н4** | Создание из кнопки сразу подставляет номер (текущий − 1 / + 1) и произведение; запрашивается только название, которое **можно пропустить** (§5) |
| **Н5** | Кнопка «предыдущая» для главы 1 создаёт **пролог** (с `is_front_matter: true`), а не «главу 0» |
| **Н6** | Средняя кнопка ведёт на заметку произведения; если произведение недоступно — кнопка неактивна |
| **Н7** | Блок **только для чтения**: он не редактируется вручную и не хранит данных (источник истины — `.sb/relations/`) |
| **Н8** | Блок скрывается, если у главы нет связи `contains` (свободно стоящая глава) |

**Механизм отображения (DL-129):** `code_block_processor` — собственный
обработчик кодового блока ```` ```sb-chapter-nav ````.

- Блок вставляется в тело заметки **при создании главы** (настройка
  `chapter_nav.auto_insert`, по умолчанию `true`).
- В режиме чтения кнопки настоящие; в режиме редактирования отображается
  исходник блока, а действие доступно через палитру команд и панель сущностей.
- **Почему не подмена DOM Obsidian:** по результатам исследования Front Matter
  Title патчирование чужого интерфейса хрупко и ломается на обновлениях.
  Свой кодовый блок — **публичный API** (`MarkdownPostProcessor`), он переживёт
  обновления. Компромисс: в режиме правки блок виден как текст.

**Настройки блока:**

| `key` | Тип | По умолчанию | `label` |
| --- | --- | --- | --- |
| `chapter_nav.auto_insert` | `boolean` | `true` | Добавлять блок навигации в новые главы |
| `chapter_nav.position` | `enum` | `top` | `top` / `bottom` — где рисовать блок |
| `chapter_nav.show_create_buttons` | `boolean` | `true` | Показывать «Создать главу N» вместо пропуска |
| `chapter_nav.show_book_button` | `boolean` | `true` | Показывать кнопку произведения |

## 7. Категории и фасеты

Глава **не категоризируется самостоятельно**: жанр, форма и формат — свойства
произведения. Дублирование категорий в главах нарушило бы правило
«одно место правды» и создало бы риск рассинхрона (глоссарий: *денормализация*).

Допустимы только свободные `tags` (например `#beta-read`).

## 8. Команды создания

| Команда | Что делает |
| --- | --- |
| `create-object` → `chapter` | диалог из §5 (произведение → номер → название) + связь `contains` + блок навигации |
| `sb-create-adjacent-chapter` | создать соседнюю главу относительно текущей (используется кнопками Н3–Н5) |
| `sb-renumber-chapters` (этап 2) | перенумеровать главы произведения после вставки/удаления |

**Удаление главы:** связь `contains` удаляется каскадно (ADR-009, Р11).
Номера остальных глав **не пересдвигаются автоматически** — это операция
`sb-renumber-chapters` с явным подтверждением.

## 9. Валидация

| Правило | Уровень | Смысл |
| --- | --- | --- |
| **`chapter.contains.required`** | error | у главы должна быть ровно одна связь `contains` с объектом-произведением |
| **`relation.contains.single_record`** | error | `contains` хранится один раз; `part_of` не дублируется отдельной записью |
| **`relation.order.unique_per_subject`** | error | `chapter_number` уникален в пределах одного произведения |
| **`chapter.title.fallback`** | error | при пустом `chapter_title` заголовок равен «Глава {N}» (инвариант И7) |
| **`relation.order.no_gap`** | warning | разрыв нумерации (есть 5 и 7, нет 6) — подсказка «создать главу 6» |
| **`chapter.number.positive`** | warning | `chapter_number` ≤ 0 при `is_front_matter: false` |
| **`relation.subject.has_parts`** | info | у произведения нет ни одной главы |

## 10. Открытые вопросы

| # | Вопрос | Рекомендация |
| --- | --- | --- |
| 1 | ~~Нужен ли `chapter_number` для пролога/эпилога?~~ | **ЗАКРЫТ 2026-10-23 (ответ А, DL-230): нет** — при `is_front_matter: true` номер не обязателен; при отсутствии или `false` — обязателен (условный `required` в `schema/entities/chapter.schema.json` через if/then/else). И7 действует только для нумерованных частей |
| 2 | Дробные номера (7.5) разрешить? | **Да**, `precision: 1` — иначе вставка интерлюдии ломает нумерацию. *Схема батча 3 следует рекомендации (тип `number`, дробные допустимы; `precision` — настройка показа); формально вопрос остаётся открытым до подтверждения* |
| 3 | Перенумерация при вставке главы в середину? | **Вручную**, командой `sb-renumber-chapters` (этап 2); автоперенумерация опасна |
| 4 | Глава может входить в два произведения (переиздание)? | **Нет** в MVP (`object_to_subject: 0..1`); при необходимости — копия главы |
| 5 | Хранить текст главы в той же заметке или в отдельном `.md`? | **В той же** — заметка главы и есть её текст, frontmatter сверху |
