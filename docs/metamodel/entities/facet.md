# Facet (Фасет) — системный тип

> **Группа:** ядро, системные (метамодель) · **Префикс:** `FACET` · **`abstract`:** нет —
> экземпляры создаются (экземпляр — конкретное измерение классификации, «Жанр», «Настроение»)
> Карточка **сокращённая** (мера M1 ADR-006): состав полей задан `01-classification` §2.2,
> карточка систематизирует и ссылается, не дублируя.

## 1. Назначение

Отдельное **измерение** классификации и **носитель правил**: настройки иерархии
(`hierarchy_mode`), кардинальность назначения (`assignment_cardinality`) и требования к корням
задаются на фасете, а не на таксономии, потому что у разных измерений одной таксономии
правила разные. С ADR-007 фасет — **самостоятельный объект метамодели**: он может входить
в таксономию, а может не входить (независимый фасет — самый частый случай).

Именно фасет закрывает противоречие **C-05**: обязательность `categories` задаётся не
универсальным ядром объекта, а кардинальностью фасета. Для «Жанра» (`1..N`) жанр обязателен;
для «Настроения» (`0..N`) — нет; у черновика может не быть ни одной категории, и это не ошибка.

## 2. Состав полей (норма — `01-classification` §2.2)

| Поле | Смысл |
|---|---|
| `taxonomy` | ссылка на `taxonomy`, **`0..1`** — таксономия необязательна (ADR-007) |
| `allowed_object_types` | область применения; пусто = наследуется от таксономии, иначе ограничений нет; семантика потомков и абстрактных типов — `07-hierarchy` §5, §7 (DL-208/209) |
| `hierarchy_mode` | `strict` (дерево; **по умолчанию**) / `polyhierarchical` (сеть) — перечисление §3.5 `05-enumerations` |
| `assignment_cardinality` | сколько категорий фасета можно назначить одному объекту: `0..1`, `1`, `0..N` (**по умолчанию**), `1..N` |
| `root_requirement_min` / `root_requirement_max` | сколько корневых категорий должно/может быть (по умолчанию `0` / `null`) |

**Наследование значений по умолчанию** (три ступени): значение фасета → значение таксономии →
таблица умолчаний §2.2. **Согласованность:** если `allowed_object_types` заданы и там, и там,
значение фасета должно быть подмножеством значения таксономии (`facet.allowed_types.conflict`,
warning).

## 3. Примеры (реестр предложенных фасетов — `02-entities` §7)

Утверждены: «Жанр» (`1..N`, минимум один корень), «Форма произведения» (`0..1`),
«Настроение» (`0..N`), «Вид знания» (`0..1` — пять видов знания стали категориями по
DL-050/057), «Носитель» (`0..1`). Частично: «Вид коллекции» (Франшиза/Галерея — открытый
вопрос этапа 2). Пример независимого фасета — «Тема» (ADR-007).

## 4. Где живёт и как создаётся

Markdown-заметка в `Metamodel/**` (ADR-002). Создание — **только командами** (ADR-004, П1–П6).
Выделенная команда `create-facet` описана в ADR-004 и `01-classification` §7, но в реестр
команд MVP (`mvp-scope` §2.3, 18 команд) не входит — расхождение зафиксировано, решение
**DL-218 предложено** (рекомендация: экземпляр фасета создаёт универсальная команда
`create-object`, выделенная обёртка — этап 2; счётчик 18 не меняется).

## 5. Связи с другими типами метамодели

- `taxonomy` — необязательная принадлежность (`0..1`);
- `category` — категория принадлежит **ровно одному** фасету;
- `object_type` — область применения через `allowed_object_types`;
- экземпляры объектов — назначение через системное поле `categories` (`04-attributes` §2);
  фасет назначения **вычисляется через категорию** и в объекте отдельно не хранится (§2.4).

## 6. Валидация

Группа **E** реестра: `facet.taxonomy.exists` (error), `facet.allowed_types.conflict` (warning),
`facet.root_requirement` (warning), `assignment.type_allowed` (error), `assignment.cardinality`
(error при `1` и `1..N`, warning при превышении `0..1`); правила на данных —
`facet.genre.required_for_book` (error), `facet.genre.not_form` (warning, граница DL-126).
Новых правил карточка не добавляет.

## 7. Открытые вопросы

Состав команд классификации — DL-218 (предложено, не блокирует); см. §4.

## 8. Этап реализации и модуль

Этап **B**; модуль `classification-service`; команда MVP — `assign-category`
(назначение категорий с проверкой кардинальности и области применения).
