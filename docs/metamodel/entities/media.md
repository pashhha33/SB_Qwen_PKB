# Media (обёртка медиафайла)

> [!info] Статус документа
> **Карточка создана по требованиям пользователя от 2026-10-22** (DL-140…DL-149) и закрывает
> ожидание DL-088: состав полей типа `media` больше **не предварительный**.
> Разделы 5 и 7 описывают поведение обёртки в базе — это требования к плагину, а не только к схеме.
> Состав `media_creation_method` и перечень условных свойств **ждут подтверждения** (раздел 10).

## 1. Назначение

`media` — это **запись о файле**, а не сам файл. Файл лежит в хранилище как вложение
(`Attachments/cover.jpg`), а обёртка хранит всё, что про этот файл известно: что это, зачем оно,
как появилось и где используется.

**Бытовая аналогия.** Файл — это фотография в альбоме. Обёртка — подписанный конверт с этой
фотографией: на конверте написано, кто на снимке, когда и чем он сделан, и в какой альбом вложен.
Фотографию можно переложить, а конверт остаётся карточкой в каталоге.

**Зачем нужен отдельный тип, а не просто файл:**

| Задача | Без обёртки | С обёрткой |
|---|---|---|
| Одно изображение — обложка книги **и** иллюстрация главы | Две копии файла или одна ссылка без смысла | Один объект с двумя ролями (мультивыбор `role`) |
| Узнать, чем сделано изображение (фото, ИИ, скан) | Негде хранить | Свойство `creation_method` + условные поля |
| Найти все необёрнутые изображения в хранилище | Ручной просмотр папок | Индекс `path → id` и команда разбора «сирот» |
| Показать обложку в карточке Bases | Ссылка на заметку не рисуется как картинка | Теневое свойство `cover_src` (см. §7.2) |
| Встроить изображение в заметку по смысловой ссылке | `![[cover.jpg]]` — путь может измениться | `![[MEDIA-….md]]` — путь меняется внутри обёртки |

## 2. Признаки типа

- поле `type` равно `media`;
- имя файла начинается с `MEDIA-`;
- заполнено свойство `file` (обязательно) и `media_kind`.

## 3. Контрпримеры

| Что | Почему не `media` | Что это |
|---|---|---|
| Сам файл `Attachments/cover.jpg` | Файл не имеет frontmatter и не объект модели | Вложение, на которое ссылается обёртка |
| Ссылка на изображение в тексте заметки | Это **встраивание**, а не запись | Wikilink или embed; может быть обёрнут по кнопке (§7.3) |
| Музыкальный трек как произведение | У трека есть автор, альбом, длительность — это произведение | Тип `music_track` (этап 2), ссылается на `media` вида `audio` (вопрос 9 реестра типов) |
| Обложка как значение свойства `cover` | Значение свойства — **ссылка** на объект `media` | Тип значения `media_reference` (ADR-008), а не тип объекта |
| PDF-инструкция с шагами | Это документ со смыслом, который читают | Тип `guide` (этап 2); `media` вида `document` — только для файла как носителя |
| Кадр из фильма, сохранённый как картинка | Это изображение, но произведение — фильм | Обёртка `media` со связью `part_of` на произведение (этап 2) |

## 4. Атрибуты

Обязательны системные атрибуты плюс `file` и `media_kind`.

### 4.1. Базовые свойства

| Поле | Подпись | Тип значения | `cardinality` | Обязательно | Допустимые значения | Пример |
|---|---|---|---|---|---|---|
| `file` | Файл | ссылка на вложение (wikilink) | `1` | **да** | существующий файл хранилища | `"[[Attachments/cover.jpg]]"` |

| `creation_method` | Способ создания | `text` (перечисление `media_creation_method`) | `0..N` | нет | **8 значений**, мультивыбор (DL-141) | `[photo, ai_generated]` |
| `origin` | Происхождение файла | `text` (перечисление `media_origin`) | `0..1` | нет | 7 значений (DL-145) | `clipboard` |

| `height_px` | Высота, пикс | `number` | `0..1` | нет | кэш, сверяется с файлом | `1800` |
| `file_size` | Размер файла | `number` (байты) | `0..1` | нет | кэш | `482113` |
| `file_hash` | Отпечаток файла | `text` | `0..1` | нет | SHA-256, только при включённой настройке | `a1b2…` |
| `source_url` | Источник в сети | `text` | `0..1` | нет | `http(s)://…` | `https://unsplash.com/…` |
| `license` | Лицензия | `text` | `0..1` | нет | свободный текст | `CC BY 4.0` |
| `copyright_holder` | Правообладатель | `text` | `0..1` | нет | — | — |
| `credit` | Подпись авторства | `text` | `0..1` | нет | требуемая подпись авторства | «Фото: Иван Петров» |
| `description` | Описание | `text` | `0..1` | нет | — | — |
| `categories` | Категории | `object_reference` → `category` | `0..N` | задаёт фасет | — | — |
| `tags` | Метки | `text` | `0..N` | нет | свободные | `избранное` |

**Про кэш (`width_px`, `height_px`, `file_size`, `file_hash`).** Это **не** источник истины, а
ускоритель: значения читаются из файла при сохранении обёртки и сверяются по команде. Расхождение
— `warning` с предложением пересчитать (`media.dimensions.stale`). Принцип тот же, что у
`chapter_count` в книге: производные данные не должны становиться второй копией правды (DL-118).

### 4.2. Условные свойства: включаются значением `creation_method` (DL-141)

Операция `includes_any` — `creation_method` допускает несколько значений: коллаж из фотографии,
доработанной нейросетью, законно содержит `[collage, photo, ai_generated]` и показывает все три
группы полей. Механизм — [[../04-attributes#11. Условные свойства — механизм applies_when|атрибуты §11]],
правила М1–М7: смена способа создания **не удаляет** введённые значения.

| Поле | Подпись | Тип | `creation_method` включает |
|---|---|---|---|
| `ai_model` | Модель | `text` `0..1` | `ai_generated` |
| `ai_prompt` | Промпт | `text` `0..1` | `ai_generated` |
| `ai_negative_prompt` | Негативный промпт | `text` `0..1` | `ai_generated` |
| `ai_seed` | Сид | `text` `0..1` | `ai_generated` |
| `ai_sampler` | Сэмплер | `text` `0..1` | `ai_generated` |
| `ai_steps` | Шаги | `number` `0..1` | `ai_generated` |
| `ai_base_image` | Исходное изображение | `media_reference` `0..1` | `ai_generated` (img2img) |
| `ai_generated_on` | Дата генерации | `datetime` `0..1` | `ai_generated` |
| `captured_at` | Дата съёмки | `datetime` `0..1` | `photo`, `screenshot` |
| `capture_device` | Устройство | `text` `0..1` | `photo` |
| `capture_location` | Место съёмки | `text` `0..1` | `photo` |
| `art_tool` | Инструмент | `text` `0..N` | `drawing` |
| `art_medium` | Материал | `text` `0..N` | `drawing` |
| `software_used` | Программа | `text` `0..N` | `digital_art`, `render` |
| `render_engine` | Движок рендера | `text` `0..1` | `render` |
| `source_materials` | Исходные материалы | `media_reference` `0..N` | `collage` |
| `scan_source` | Что отсканировано | `text` `0..1` | `scan` |
| `scan_dpi` | Разрешение сканирования | `number` `0..1` | `scan` |
| `screenshot_of` | Что на снимке | `text` `0..1` | `screenshot` |

**Итого: 16 базовых + 19 условных = 35 свойств.** Обязательны только `file` и `media_kind`.

### 4.3. Пояснения к атрибутам

- **`creation_method` и `media_kind` отвечают на разные вопросы** (граница по образцу
  `format` / `media_kind` у книги, DL-135): `media_kind` — «что за файл лежит в хранилище»,
  `creation_method` — «как он появился». Скриншот — это `media_kind: image` и
  `creation_method: screenshot`.
- **`role` — мультивыбор** (требование пользователя, DL-142): одно изображение может быть
  одновременно обложкой книги и иллюстрацией к главе. Роли расширены с 8 до 13 значений —
  [[../05-enumerations#3.10. Роль медиа media_role|§3.10]].
- **`role` и `creation_method` не дублируют друг друга:** роль — «зачем оно здесь»,
  способ создания — «как оно сделано». У одного фото может быть две роли и один способ создания.
- **`ai_*` — восемь полей, потому что их требует воспроизводимость.** Если генерация понравилась,
  её хочется повторить; без модели, промпта и сида повтор невозможен. Поля необязательные:
  заполняется то, что известно. Правило `media.ai.model_required` даёт `warning`, если выбран
  способ `ai_generated`, но модель не указана.
- **`ai_base_image` и `source_materials` ссылаются на другие обёртки**, а не на файлы: у исходника
  может быть своя история. Это же даёт цепочку происхождения (коллаж → его элементы).
- **`origin` нужен мастеру создания и разбору «сирот»** (§7.3, §7.4): зная, откуда файл попал
  в хранилище, плагин может подсказать осмысленное имя и папку.
- **`license`, `copyright_holder`, `credit` — три поля, а не одно.** Лицензия (чем разрешено
  пользоваться), правообладатель (кому принадлежит) и требуемая подпись (что писать под картинкой)
  — разные сведения; в одном поле они превращаются в кашу, которую нельзя проверить.

## 5. Связи

| Связь | Роль отсюда | Роль оттуда | Куда | Кардинальности | `link_mode` | Обязательна |
|---|---|---|---|---|---|---|
| — (обратная) | — | — | `book.cover`, `person.portrait`, `chapter.illustration` | — | ссылка хранится **в объекте-владельце** | нет |
| `depicts` | изображает | изображено на | `person`, `character`, `place` | `0..N` / `0..N` | `direct` | нет (этап 2) |
| `part_of` (обратная `contains`) | входит в | содержит | `book`, `chapter` | `0..N` / `0..1` | `reified` | нет (этап 2) |
| `derived_from` | производное от | исходник для | `media` | `0..1` / `0..N` | `direct` | нет (этап 2) |

**Важно:** в MVP у обёртки **нет обязательных исходящих связей**. Обёртка существует и сама по себе
(«просто картинка в хранилище»), и как значение свойства чужого объекта. Связь «обложка» объявляется
не здесь, а свойством `cover` типа `book` — направление всегда от владельца к медиа
(принцип ADR-009: свойство объявляет `link_mode`).

## 6. Правила валидации

Специфичные для типа (полные формулировки — [[../../validation/rules|единый реестр]], группа J):

| ID правила | Формулировка | Уровень |
|---|---|---|
| `media.file.required` | `file` заполнен | error |
| `media.file.exists` | Файл существует в хранилище | error |
| `media.file.is_attachment` | Файл лежит в одной из папок вложений и имеет допустимое расширение | warning |
| `media.kind_matches_extension` | `media_kind` соответствует расширению файла | warning |
| `media.kind.enum` | `media_kind` входит в закрытый список из 5 значений | error |
| `media.roles.enum` | Каждое значение `role` входит в `media_role` (13 значений) | error |
| `media.creation_method.enum` | Каждое значение `creation_method` входит в `media_creation_method` (8 значений) | error |
| `media.origin.enum` | `origin` входит в `media_origin` (7 значений) | error |
| `media.ai.model_required` | При `creation_method: ai_generated` заполнено `ai_model` | warning |
| `media.ai.prompt_present` | При `creation_method: ai_generated` заполнен `ai_prompt` | warning |
| `media.capture.required_for_photo` | При `creation_method: photo` заполнено хотя бы одно из `captured_at`, `capture_device` | info |
| `media.scan.dpi_positive` | `scan_dpi` больше нуля | error |
| `media.file.single_wrapper` | Один файл не обёрнут дважды: нет двух объектов `media` с одним `file` | error |
| `media.body.embed_synced` | В теле заметки есть встраивание того же файла, что и в `file` (инвариант И8) | warning |
| `media.dimensions.stale` | Кэш `width_px` / `height_px` / `file_size` расходится с файлом | warning |
| `media.hash.mismatch` | `file_hash` не совпадает с отпечатком файла (только при включённой настройке) | warning |
| `media.source_url.format` | `source_url` начинается с `http://` или `https://` | warning |
| `media.referrers.shadow_synced` | Теневое свойство `*_src` у ссылающегося объекта совпадает с `file` обёртки | warning |

Общие правила (`object.*`, `value.*`, `property.applies_when.*`) применяются автоматически.

**Инвариант И8 (новый):** тело заметки-обёртки содержит встраивание файла `![[{file}|…]]` как
первый элемент. Инвариант нужен не для красоты, а как **страховка показа**: даже с отключённым
плагином `![[MEDIA-….md]]` в чужой заметке покажет изображение средствами самого Obsidian (§7.1).

## 7. Поведение обёртки в базе

Требования пользователя 2.1–2.4 разложены на механизмы. Для каждого указано, **чем** это
реализуется и **какова цена**.

### 7.1. Встраивание: `![[MEDIA-….md]]` показывает изображение (требование 2.1)

**Два уровня, работают вместе:**

| Уровень | Механизм | Что даёт | Цена |
|---|---|---|---|
| **У1 — гарантия** (MVP) | Тело обёртки содержит `![[{file}\|{title}]]` (инвариант И8); плагин вставляет строку при создании и чинит при смене `file` | Obsidian штатно раскрывает встраивание заметки, поэтому изображение видно **без единой строчки патчей**: в редакторе, в режиме чтения, в экспорте и в Publish | Занимает одну строку в теле обёртки |
| **У2 — улучшение** (MVP) | `registerMarkdownPostProcessor`: находим `div.internal-embed[markdownembed][src$="MEDIA-….md"]`, читаем объект, подменяем содержимое на `<img src={app.vault.getResourcePath(file)}>` с подписью и кнопками | Красивый вывод: подпись, размер, кнопки «открыть обёртку» / «где используется»; поддержка `![[MEDIA-….md\|400]]` (ширина) и `![[MEDIA-….md\|подпись]]` | Кратковременное мерцание: сначала Obsidian рисует штатное встраивание, затем оно заменяется |

**Только публичный API.** Постпроцессоры и `getResourcePath()` документированы; патчи чужого
рендеринга — нет. Обоснование то же, что в ADR-003 и в исследовании
[[../../integrations/research-front-matter-title-stability|стабильности Front Matter Title]]:
мы не повторяем ошибку плагинов, ломающихся на обновлениях Obsidian.

**Резервное поведение:** файла нет → значок вида медиа, имя и кнопка «найти замену»;
`media_kind` не `image` → плеер для `audio`/`video` (штатный), карточка файла для `document`.

### 7.2. Карточки Bases: как получить картинку из обёртки (требование 2.2)

> [!danger] Проверенное ограничение Bases
> По документации Obsidian, свойство-изображение в карточном виде принимает **только**: ссылку на
> локальное вложение, внешний URL или hex-код цвета. Ссылка на **заметку** (то есть на обёртку)
> изображением не считается и картинкой не рисуется. Формула `image(file(...))` работает в табличном
> виде, а в карточном по ней есть открытая проблема сообщества. Вывод: «в лоб» требование 2.2
> не выполняется — нужен посредник.

**Решение: теневое свойство (`shadow property`).** Рядом со свойством `cover` (тип значения
`media_reference`, `media_target: object`) плагин ведёт производное свойство **`cover_src`**,
в котором лежит ссылка на сам файл вложения:

```yaml
---
type: book
cover: "[[MEDIA-01J8Z6M4K2Q7V9X3N5B0C1D2E9.md|Обложка «Мастер и Маргарита»]]"
cover_src: "[[Attachments/covers/master-and-margarita.jpg]]"   # ← пишет только плагин
---
```

| Параметр | Значение |
|---|---|
| Соглашение об имени | `{key}_src` (настройка `media.shadow_suffix`, значения `_src` / `_file`) |
| Что хранит | Wikilink на файл вложения из `media.file` (при `media_target: file` — то же значение, что и само свойство) |
| Кто пишет | Только плагин: при выборе обёртки, при смене `file` внутри обёртки, при удалении обёртки |
| Можно ли править руками | Технически да; правило `media.referrers.shadow_synced` выдаёт `warning` и предлагает команду `sb-resync-media-shadows` |
| Зачем | Карточный вид Bases указывает «Image property» = `cover_src` и рисует обложки |
| В интерфейсе плагина | Скрыто по умолчанию (настройка «показывать служебные свойства») |
| Каскад | Удалили обёртку → `cover` очищается по правилам ADR-009, `cover_src` очищается вместе с ним |

**Что это стоит:** одно дополнительное свойство на каждое `media_reference`-свойство и обязанность
держать его синхронным. Это **осознанная плата** за работающие обложки в Bases — альтернативы
без патчей внутренностей Bases нет.

**Дополнительно (не MVP):** собственное представление-галерея плагина рисует миниатюры напрямую
через `getResourcePath()` и в теневом свойстве не нуждается.

### 7.3. Кнопки у изображений в тексте (требование 2.3)

| Состояние | Что видно | Действие |
|---|---|---|
| Изображение вставлено напрямую (`![[photo.jpg]]`), обёртки нет | Кнопка **«Создать обёртку»** | Мастер из §7.4 с предзаполненным источником «файл уже в хранилище» |
| Изображение обёрнуто (на файл ссылается объект `media`) | Кнопка **«Открыть обёртку»** + счётчик использований | Переход к `MEDIA-….md`; меню «где используется» |
| В тексте стоит `![[MEDIA-….md]]` | Кнопка **«Открыть обёртку»** | То же |
| Файла нет | Кнопка **«Найти замену»** | Выбор другого файла, `file` обновляется |

**Механизм:** `registerEditorExtension` (CodeMirror 6 `ViewPlugin` + `Decoration.widget`) для
режима Live Preview и постпроцессор для режима чтения. Кнопка рисуется **при наведении** на
изображение, чтобы не засорять страницу.

**Как плагин узнаёт, обёрнуто ли изображение:** индекс `путь к файлу → id обёртки`, который
строится по всем объектам `media` и живёт в кэше `.sb/cache/media-index.json`; обновляется по
событиям `vault` (создание, изменение, удаление, переименование). Индекс нужен и для §7.4
(«свободные изображения»), поэтому он один на обе задачи.

**Риски и меры:**

| Риск | Мера |
|---|---|
| Украшения пересчитываются на каждое изменение документа → тормоза на больших заметках | Пересчёт с debounce; проверка только видимой области (`visibleRanges`) |
| Индекс устарел после внешнего изменения файлов | Перестроение по команде `sb-rebuild-media-index`; `warning` при расхождении |
| Live Preview и режим чтения рисуются по-разному | Два независимых кода пути с одним источником данных (индекс) |

### 7.4. Мастер создания обёртки (требование 2.4)

Команды: `sb-create-media` (из палитры), «Создать обёртку» у изображения (§7.3),
«Новая обёртка» в модалке выбора медиа (ADR-008).

**Шаги мастера:**

| Шаг | Что спрашиваем | По умолчанию | Обязательно |
|---|---|---|---|
| 1 | **Имя обёртки** | Имя файла без расширения | да (без имени объект не создать: `object.title.required`) |
| 2 | **Источник изображения**: буфер обмена / свободные файлы хранилища / локальный диск / файл уже в хранилище | Последний использованный | да |
| 3 | **Способ создания** (`creation_method`, мультивыбор) | Подсказка по источнику: буфер → `screenshot` или `photo`; диск → `photo`; папка ИИ-инструмента → `ai_generated` | нет |
| 4 | **Роль** (`role`, мультивыбор) | Подсказка из контекста: если мастер открыт из свойства `cover` — `cover` | нет |
| 5 | **Прикрепить к объекту** | Объект и свойство, из которого открыли мастер | нет |

**Источники и как они устроены:**

| Источник | Механизм | Что важно знать |
|---|---|---|
| **Буфер обмена** | (а) `navigator.clipboard.read()` — асинхронное чтение; (б) **область вставки в модалке**: `paste`-событие на `contenteditable`, берём `clipboardData.files[0]` | Требование пользователя учтено буквально: вариант (а) надёжен, когда картинка скопирована **из браузера** или снята скриншотом, и часто отказывает, когда файл скопирован **в проводнике**. Вариант (б) не зависит от async-clipboard и ловит то, что (а) не смог. Если оба не дали данных — внятное сообщение и переход к другим источникам, а не «молча ничего не произошло» |
| **Свободные файлы хранилища** | Список изображений из папок вложений (настройка `attachmentFolders`), **исключая** уже обёрнутые (индекс из §7.3); миниатюры через `getResourcePath()`, фильтр по имени | «Свободный» = на файл не ссылается ни одна обёртка. Это же список для команды разбора «сирот» |
| **Локальный диск** | `<input type="file">` (нативный диалог) → чтение через `app.vault.adapter.readBinary` → запись в папку вложений | Obsidian — браузерное приложение, прямого пути к диску нет; файл **копируется** в хранилище. Исходный путь запоминается в `description`/`source_url` только если пользователь согласен |
| **Файл уже в хранилище** | Быстрый выбор по пути (из кнопки §7.3) | Ничего не копируется |

**Что происходит после создания:**

1. файл оказывается в папке вложений (если источник — буфер или диск);
2. создаётся заметка `MEDIA-{ULID}.md`: системные атрибуты, `file`, `media_kind` по расширению,
   `role`, `creation_method`, `origin` = источник из шага 2;
3. в тело вставляется `![[{file}|{title}]]` (инвариант И8);
4. кэш `width_px` / `height_px` / `file_size` заполняется из файла;
5. если на шаге 5 выбран объект — записывается значение свойства **и** теневого `*_src` (§7.2);
6. индекс обновляется;
7. **если мастер открыт из кнопки у вставленного изображения** — предлагается заменить
   `![[photo.jpg]]` на `![[MEDIA-….md]]`. Замена **только по явному согласию**: молча переписывать
   текст заметки запрещено (спецификация v1.0 §19).

**Настройки мастера:** папки вложений, шаблон имени (`{filename}` / `{title}` / `{date}-{filename}`),
поведение при совпадении имён (`ask` / `rename_auto`), включён ли `file_hash`.

### 7.5. Сводка: что реализуемо и чем

| Требование | Реализуемо | Механизм | Оговорка |
|---|---|---|---|
| 2.1 `![[обёртка]]` показывает изображение | **да** | Инвариант И8 + `registerMarkdownPostProcessor` + `getResourcePath()` | Мерцание при замене штатного встраивания |
| 2.2 Картинка из обёртки в карточках Bases | **да, через посредника** | Теневое свойство `*_src` со ссылкой на файл | Свойство-изображение Bases не принимает ссылку на заметку; формула `image()` в карточном виде ненадёжна |
| 2.3 Кнопки «создать / открыть обёртку» | **да** | `registerEditorExtension` (Live Preview) + постпроцессор (чтение) + индекс `path → id` | Производительность на больших заметках: debounce, `visibleRanges` |
| 2.4 Мастер создания с четырьмя источниками | **да** | Собственная модалка; `navigator.clipboard.read()` + `paste`-fallback; `<input type="file">`; `adapter.readBinary` | Буфер обмена ненадёжен для файлов из проводника — поэтому область вставки и три других источника |

## 8. Представления

| Представление | Что показывает | Статус |
|---|---|---|
| Галерея обёрток | Миниатюры, роли, способ создания, где используется | MVP (собственное) |
| Таблица медиа | Имя, вид, роли, файл, размер | MVP через Bases |
| Свободные изображения | Файлы вложений без обёрток + кнопка «создать обёртку» | MVP (собственное) |
| Обложки книг | Карточки Bases со свойством-изображением `cover_src` | MVP через Bases (§7.2) |
| Узел графа | Обёртка и объекты, которые на неё ссылаются | MVP |

## 9. Пример экземпляра

### Корректный: обложка книги, обработанная нейросетью

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2E9
type: media
title: Обложка «Мастер и Маргарита»
aliases:
  - Обложка «Мастер и Маргарита»
created_at: 2026-10-22T16:05
updated_at: 2026-10-22T16:05
file: "[[Attachments/covers/master-and-margarita.jpg]]"
media_kind: image
role:
  - cover
creation_method:
  - photo
  - ai_generated
origin: local_disk
width_px: 1200
height_px: 1800
file_size: 482113
captured_at: 2019-07-14T18:40
capture_device: Canon EOS R
ai_model: SDXL 1.0
ai_prompt: book cover, dark fantasy, cat with monocle, oil painting texture
ai_seed: "778213"
ai_steps: 32
ai_generated_on: 2026-10-22T16:00
license: CC BY-NC 4.0
credit: "Фото: Иван Петров; обработка: автор базы"
description: Исходное фото сделано в Кисловодске, доработано нейросетью.
---

![[Attachments/covers/master-and-margarita.jpg|Обложка «Мастер и Маргарита»]]
```

Первая строка тела — инвариант И8: именно она показывает изображение при встраивании
`![[MEDIA-01J8Z6M4K2Q7V9X3N5B0C1D2E9.md]]` в заметке о книге, даже если плагин выключен.

### Некорректный и почему

```yaml
---
type: media
title: cover
file: "[[Attachments/несуществующий.jpg]]"
media_kind: видео
role:
  - обложка
creation_method:
  - ai_generated
---
```

| Нарушение | Правило | Сообщение пользователю |
|---|---|---|
| Нет `id` | `object.id.format` | «У записи нет идентификатора. Создайте её командой плагина» |
| Файла нет в хранилище | `media.file.exists` | «Файл „Attachments/несуществующий.jpg“ не найден. Укажите другой или восстановите файл» |
| `media_kind: видео` — кириллица | `enum.value.no_mixed_script`, `media.kind.enum` | «Вид медиа задаётся ключом: image, audio, video, document, other» |
| `role: обложка` — кириллица | `media.roles.enum` | «Роль задаётся ключом из списка: cover, banner, logo…» |
| Выбран `ai_generated`, но модели нет | `media.ai.model_required` | «Указан способ „Генерация ИИ“, но не заполнено поле „Модель“» |
| В теле нет встраивания файла | `media.body.embed_synced` | «В заметке нет встраивания изображения. Плагин может добавить его автоматически» |
| Этот же файл уже обёрнут другой обёрткой | `media.file.single_wrapper` | «На этот файл уже есть обёртка MEDIA-…. Открыть её?» |

## 10. Открытые вопросы

- [ ] **10.1. Состав `media_creation_method` (8 значений)** — подтверждение пользователя.
      Отдельно: нужны ли `render` (3D) и `scan`, или для личной базы достаточно пяти.
- [ ] **10.2. Восемь полей `ai_*`** — не слишком ли детально для MVP. Альтернатива: оставить
      `ai_model`, `ai_prompt`, `ai_seed`, остальное добавить по мере надобности.
- [ ] **10.3. Имя теневого свойства**: `cover_src` или `cover_file`. Предложение ассистента:
      `_src` — короче и не путается со свойством `file` самой обёртки.
- [ ] **10.4. Обязателен ли `file_hash`** (контроль подмены файла). Предложение: настройка,
      по умолчанию выключено — на большом хранилище считание отпечатков дорого.
- [ ] **10.5. Один файл — одна обёртка** (правило `media.file.single_wrapper`, `error`).
      Альтернатива: разрешить несколько обёрток на один файл (разные роли в разных контекстах)
      и понизить уровень до `warning`.
- [ ] **10.6. Заменять ли `![[photo.jpg]]` на `![[MEDIA-….md]]` автоматически** после создания
      обёртки. Предложение: только по явному согласию (спецификация v1.0 §19).
- [ ] **10.7. Поведение для `audio` и `video`**: тот же набор правил или отдельная карточка.
      Предложение: общий каркас, длительность и плеер — этап 2.
- [ ] **10.8. Скачивание из сети по `source_url`** — вне области (проект офлайн) или этап 2.

## 11. Этап реализации и модуль

- Этап: **1 (MVP)** — схема, валидация, мастер создания, встраивание, кнопки, теневые свойства.
- Этап 2: `depicts`, `derived_from`, галерея в стандартном автодополнении Obsidian, длительность
  аудио и видео, пакетный разбор «сирот».
- Модули плагина: `media-index`, `media-wizard`, `embed-postprocessor`, `editor-decorations`,
  `shadow-sync`, `bases-adapter`.
- Обоснование: без `media` не работают `book.cover` и `person.portrait`, а карточные представления
  Bases теряют обложки — это один из главных сценариев пользователя.
