# 04. Атрибуты

> [!info] Статус документа
> Нормативный. Основание — [[../adr/ADR-006-system-attributes-value-types-media|ADR-006]],
> принят 2026-10-22. Имена полей — по [[../adr/ADR-003-bilingual-keys-and-label-layer|ADR-003]].

## 1. Два рода полей

| | Системные атрибуты | Предметные свойства |
|---|---|---|
| Набор | **Закрыт**, задан кодом плагина | **Открыт**, задаётся метамоделью |
| Есть у кого | У каждого объекта | У объектов тех типов, где объявлены |
| Можно отключить | Нет | Да |
| Можно переопределить тип значения | Нет | — |
| Можно уточнить обязательность в наследнике | Нет | Да |
| Добавление нового | Ломающее изменение MAJOR | Не требует изменения кода плагина |
| Кто проверяет | Ядро плагина, всегда | Движок схемы, по определениям |
| Где описаны | Раздел 3 этого документа | Объекты типа `property` |

**Смысл разделения:** системные атрибуты — это то, без чего объект не является объектом модели
(идентичность, тип, имя, время). Предметные свойства — то, что описывает объект по существу
(автор, год издания, статус проекта). Первые изменять нельзя, вторые добавляются свободно.

## 2. Типы значений: семь, набор закрыт

| `value_type` | Подпись | Что хранит | Пример значения | Множественность |
|---|---|---|---|---|
| `text` | Текст | Строка | `Мастер и Маргарита` | задаёт `cardinality` |
| `number` | Число | Целое или дробное | `1967`, `7.5` | задаёт `cardinality` |
| `date` | Дата | `YYYY-MM-DD`, локальная | `2026-10-22` | задаёт `cardinality` |
| `datetime` | Дата и время | `YYYY-MM-DDTHH:mm`, локальное | `2026-10-22T14:35` | задаёт `cardinality` |
| `boolean` | Логическое | `true` / `false` | `true` | только `1` или `0..1` |
| `object_reference` | Ссылка на объект | Ссылка на объект метамодели или данных | `"[[PERSON-01J8….md|Михаил Булгаков]]"` | задаёт `cardinality` |
| `media_reference` | Ссылка на медиа | Ссылка на объект типа `media` | `"[[MEDIA-01J8….md|Обложка]]"` | задаёт `cardinality` |

**Убраны из исходного набора:** `Список` и `Список ссылок`. Множественность задаётся **только** полем
`cardinality` у свойства.

> [!note] Почему так
> Множественность — характеристика свойства, а не тип значения. Держать её в двух местах
> (тип «Список» + `cardinality`) — значит заложить будущее противоречие. Запись U-05.

### Сравнение с исходным набором

| Было (`01` §6, `02 v1.0` §2) | Стало | Комментарий |
|---|---|---|
| текст | `text` | — |
| число | `number` | — |
| дата | `date` | Формат уточнён |
| дата_время | `datetime` | Формат уточнён |
| логическое | `boolean` | — |
| список | **убрано** | Заменяется `cardinality: 0..N` + тип элемента |
| ссылка | `object_reference` | Уточнено: ссылка именно на объект |
| список_ссылок | **убрано** | Заменяется `cardinality: 0..N` + `object_reference` |
| — | `media_reference` | **Добавлено** для типа `media` |

## 3. Системные атрибуты

Есть у каждого объекта. Ключи зафиксированы и не переводятся; подписи используются в интерфейсе.

| `key` | Подпись | Тип значения | `cardinality` | Обязательность | Кто заполняет |
|---|---|---|---|---|---|
| `id` | — (не отображается) | `text` (ULID) | `1` | **обязательно** | плагин при создании |
| `type` | Тип объекта | `text` (ключ типа) | `1` | **обязательно** | плагин при создании |
| `title` | Название | `text` | `1` | **обязательно** | пользователь |
| `aliases` | Псевдонимы | `text` | `0..N` | необязательно, подчиняется инварианту И4 | плагин + пользователь |
| `created_at` | Создан | `datetime` | `1` | **обязательно** | плагин при создании |
| `updated_at` | Изменён | `datetime` | `1` | **обязательно** | плагин при сохранении |
| `categories` | Категории | `object_reference` → `category` | `0..N` | задаёт фасет | пользователь через `assign-category` |
| `tags` | Метки | `text` | `0..N` | необязательно | пользователь |

### Инварианты системного слоя

Инвариант (**термин**, см. [[../glossary/glossary|глоссарий]]) — условие, которое обязано выполняться всегда.

| ID | Инвариант | Нарушение = |
|---|---|---|
| И1 | `id` — валидный ULID, уникален в хранилище, не переиспользуется | `error` |
| И2 | `id` совпадает с ULID в имени файла; при расхождении имя файла чинится по `id` | `error`, плагин предлагает исправить имя файла |
| И3 | `type` указывает на существующий тип объекта, и этот тип не абстрактный | `error` |
| И4 | `aliases[0] == title`; остальные элементы — дополнительные псевдонимы, их порядок сохраняется | `warning`, плагин предлагает восстановить |
| И5 | `created_at` не меняется после создания; `updated_at` ≥ `created_at` | `error` |
| И6 | Ключи системных атрибутов не могут быть переопределены предметными свойствами | `error` при попытке создать свойство с таким `key` |

> [!important] Область действия таблицы
> Таблица описывает системные атрибуты **экземпляра объекта**, хранящегося как Markdown-заметка.
> У экземпляра связи (`relation`), который хранится в `.sb/relations/` (см.
> [[../adr/ADR-010-relation-storage|ADR-010]]), набор сокращён: действуют `id`, `type`, `title`,
> `created_at`, `updated_at`; `aliases`, `categories` и `tags` к связям не применяются, потому что
> на связь нельзя сослаться wikilink-ом и она не классифицируется. Основание — Р10
> [[../adr/ADR-009-relations-model|ADR-009]], запись DL-100.

### Правило для заметок, созданных вне плагина

Если `created_at` или `updated_at` отсутствуют, плагин **дописывает** их при первом сохранении через
свою команду и выдаёт `warning`. Не `error` и не молча: действие видимое и объяснимое. Это соответствует
принципу спецификации v1.0 §19 «система не должна молча переписывать неправильные данные».

## 4. Предметные свойства

Свойство — объект метамодели типа `property`.

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2EW
type: property
title: Author
key: author
label: Автор
value_type: object_reference
target_types:
  - "[[OBJECT_TYPE-….md|Человек]]"
cardinality: 1..N
required: true
scope: universal
lifecycle: standard
definition: Person or organization that created the work.
---
```

| `key` | Подпись | Тип значения | Обязательность | Допустимые значения | Примечание |
|---|---|---|---|---|---|
| `title` | Название | `text` | да | — | Системный атрибут: имя свойства как объекта |
| `key` | Ключ | `text` | да | `^[a-z][a-z0-9_]*$` | Техническое имя поля в данных. Стабильно |
| `label` | Подпись | `text` | да | — | Русское название для интерфейса. Меняется свободно |
| `value_type` | Тип значения | enum | да | семь значений из раздела 2 | Набор закрыт |
| `target_types` | Допустимые типы цели | `object_reference` → `object_type` | для `object_reference` и `media_reference` — да | — | Список типов, на которые может указывать свойство |
| `target_facet` | Фасет-справочник | `object_reference` → `facet` | нет | — | Только если свойство является словарём; см. раздел 5 |
| `link_mode` | Способ хранения связи | enum | для `object_reference` — да | `direct`, `reified` | `direct` — ссылка хранится в объекте; `reified` — связь хранится как объект `relation`. Норма будет утверждена на шаге 6 |
| `media_*` | Семь настроек медиа | различный | для `media_reference` — `media_target` обязательно | см. раздел 10 | Допускаются **только** у свойств типа `media_reference` |
| `cardinality` | Кардинальность | enum | да | `1`, `0..1`, `0..N`, `1..N` | Единственный способ задать множественность |
| `required` | Обязательно | `boolean` | да | — | Производно от `cardinality`: `1` и `1..N` подразумевают обязательность |
| `scope` | Область применения | enum | да | `universal`, `family`, `specific` | Объединяет исходные `область_применения` и `уровень` (U-06); машиночитаемая привязка — поле `object_types` (§4.1, F5-8) |
| `object_types` | Привязка к типам | `object_reference` → `object_type` | нет (семантика задаётся `scope`, §4.1) | — | Список wikilink-ов на определения типов; введён F5-8 = А (DL-250/252) |
| `lifecycle` | Жизненный цикл | enum | нет | `experimental`, `standard`, `deprecated`, `archived` | Из `01` §16 |
| `default_value` | Значение по умолчанию | любой | нет | — | Подставляется при создании объекта |
| `definition` | Определение | `text` | нет | — | Смысл поля человеческим языком |
| `service` | Служебное | `boolean` | нет, по умолчанию `false` | `true` / `false` | Свойство существует в схеме и данных, но **не предлагается для ввода**: его ведёт плагин. В MVP одно такое свойство — `sb_issues` (DL-168, [[08-views\|`08-views.md`]] §7) |
| `create_from_link` | Создание из пустой ссылки | enum | нет, по умолчанию `ask` | `ask`, `forbid`, `auto` | Только для `object_reference` и `media_reference`: разрешено ли создавать объект кликом по неразрешённой ссылке в этом свойстве. Норма — [[12-links-and-aliases\|`12-links-and-aliases.md`]] §5.4 (`accepted`, DL-187) |

### 4.1. Привязка свойства к типу (F5-8 = А, DL-250/252)

Поле **`object_types`** — список ссылок на определения `object_type`, которым принадлежит
свойство. Закрывает пробел: правила `property.key.unique_in_type`,
`property.applies_when.property_exists` («в том же типе»), наследование свойств
(`07-hierarchy` §6) и формы этапа B предполагают принадлежность, но до 1.1.0 она
не кодировалась в данных (`scope: family/specific` не имел носителя).

| `scope` | `object_types` | Смысл |
|---|---|---|
| `universal` | пусто или отсутствует | Свойство доступно всем типам |
| `family` | ровно одна ссылка на **абстрактный** тип | Свойство доступно всему семейству: потомки предка включаются автоматически (семантика DL-208) |
| `specific` | одна и более ссылок на **неабстрактные** типы | Свойство принадлежит перечисленным типам (их потомки — по наследованию, `07-hierarchy` §6) |

Правила: `property.object_types.scope_consistency` (error) и `property.object_types.exists`
(error) — группа B реестра. Наследник, уточняющий свойство родителя (`01-classification` §5),
ссылается на того же владельца; дублирование определения с тем же `key` для другого типа —
нарушение `property.key.unique_in_type` в пределах типа и его предков. Привязка **не**
заменяет `target_types` (цели ссылок) и `applies_when` (условный показ) — это три разных
механизма.

### Про `required` и `cardinality`: устранение дублирования

Два поля выражают частичное дублирование смысла. Правило согласованности:

| `cardinality` | Допустимое `required` | Смысл |
|---|---|---|
| `1` | только `true` | Ровно одно значение, обязательно |
| `1..N` | только `true` | Минимум одно значение |
| `0..1` | только `false` | Не более одного, можно без него |
| `0..N` | только `false` | Сколько угодно, можно без них |

Правило валидации `property.required.cardinality_consistency` уровня `error` не даст задать противоречивую
пару. Альтернатива — убрать `required` вовсе и выводить его из `cardinality`. **Предложение, требует
подтверждения:** оставить `required` как явное поле ради читаемости, но проверять согласованность.

## 5. Перечисление или словарь — правило выбора

Вопрос пользователя: «а если придётся использовать словарь?» — **новый механизм не нужен**.

| Способ | Как устроен | Когда применять | Пример |
|---|---|---|---|
| **Перечисление (`enum`)** | Закрытый список значений прямо в определении свойства, поле `allowed_values` | Значений мало, они стабильны и носят технический характер. Добавление значения = изменение метамодели | `hierarchy_mode: strict \| polyhierarchical` |
| **Ссылка на категорию** | `value_type: object_reference`, `target_types: [category]`, `target_facet: <фасет>` | Значений много, список пополняет пользователь, нужна иерархия или русские подписи | `categories` → фасет «Жанр»; `country_of_publication` → фасет «Страна издания» |
| **Ссылка на объект другого типа** | `value_type: object_reference`, `target_types: <предметный тип>` | Значение — самостоятельный объект со своими полями | `author` → `person` |

**Правило:**

> Значений меньше десятка и они меняются только вместе с метамоделью → **перечисление**.
> Значений много, список пополняет пользователь, нужна иерархия или подписи → **категория фасета**.

**Что автоматически даёт словарь-категория** (и не даёт перечисление):

- иерархию значений (через `parent` у категорий);
- русские подписи (`label` у категории) без изменения ключей;
- валидацию кардинальности и допустимого типа объекта;
- возможность строить представления и отборы;
- режим полиерархии, если значение законно относится к нескольким родителям.

### Пример свойства-словаря

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2EX
type: property
title: Country of publication
key: country_of_publication
label: Страна издания
value_type: object_reference
target_types:
  - "[[OBJECT_TYPE-….md|Категория]]"
target_facet: "[[FACET-….md|Страна издания]]"
cardinality: 0..1
required: false
definition: Страна издания произведения. Значения берутся из справочника фасета «Страна издания».
---
```

### Пример свойства с перечислением

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2EY
type: property
title: Status
key: status
label: Статус
value_type: text
allowed_values: [idea, active, paused, done, dropped]
cardinality: 1
required: true
default_value: idea
scope: specific
definition: Current state of the activity.
---
```

## 6. Даты и время

Полный документ — `06-time-and-intervals.md` (создаётся на шаге 7). Здесь — зафиксированная норма.

| Параметр | Норма |
|---|---|
| Хранение `date` | `YYYY-MM-DD`, локальная дата |
| Хранение `datetime` | `YYYY-MM-DDTHH:mm`, **локальное время без смещения** |
| Точность | Минуты. Секунды не храним |
| Часовой пояс | Не хранится |
| Сравнение и сортировка | Лексикографически по строке |
| Отображение | Настройка плагина, на хранение не влияет |

**Настройки отображения в плагине:**

| Настройка | Значения | По умолчанию |
|---|---|---|
| Формат даты | `YYYY-MM-DD`, `DD.MM.YYYY`, `DD MMM YYYY`, «как в файле» | `DD.MM.YYYY` |
| Формат времени | `HH:mm`, `HH:mm:ss`, не показывать | `HH:mm` |
| Относительные даты | «сегодня», «вчера», «3 дня назад» вместо абсолютных | выключено |
| Порог относительных дат | дней | 7 |

> [!warning] Известное ограничение (G-04-1)
> Локальное время без смещения ломает хронологический порядок, если заметки создаются в разных
> часовых поясах. Для личной базы в одном часовом поясе приемлемо. Если станет мешать — добавим
> необязательное поле `timezone` или переход на UTC как ломающее изменение с миграцией.

## 7. Соглашение об именовании

| Что | Формат | Пример | Проверка |
|---|---|---|---|
| Системные атрибуты | закрытый список, `snake_case` | `id`, `created_at` | сверка со списком раздела 3 |
| Ключи свойств (`key`) | `snake_case`, только латиница | `parent_type`, `publication_year` | `^[a-z][a-z0-9_]*$` |
| Имена типов (`type`) | `snake_case`, единственное число | `person`, `object_type` | то же |
| Префиксы файлов (`TYPE_PREFIX`) | `UPPER_SNAKE_CASE`, 3–20 символов (F5-7 = А, DL-253) | `PERSON`, `OBJECT_TYPE` | `^[A-Z][A-Z0-9_-]*$` + длина 3–20 (`defs#type_prefix`) |
| Значения перечислений | `snake_case`, латиница | `in_progress`, `strict` | `^[a-z][a-z0-9_]*$` |
| Подписи (`label`) | русский, с заглавной буквы | «Родительский тип» | непустая строка |

Запрещены: смешение кириллицы и латиницы в одном идентификаторе, пробелы, регистрозависимые различия
как единственный способ отличить два ключа (`Status` и `status` — это нарушение).

| ID правила | Формулировка | Уровень |
|---|---|---|

## 10. Тип значения `media_reference`: настройки и поведение

Полная норма — [[../adr/ADR-008-media-property-type|ADR-008]]. Здесь — сводка для справочного использования.

**Различие, которое важно не путать:**

| | Тип **объекта** `media` | Тип **значения** `media_reference` |
|---|---|---|
| Что это | Запись в базе, представляющая файл и его семантику | Объявление того, какого рода данные хранятся в поле и каким контролом вводятся |
| Где живёт | Заметка `MEDIA-{ULID}.md` | Определение свойства (`type: property`) |
| Поля | `file`, `media_kind`, `role`, `description` | `media_target`, `media_kinds`, `media_folders`, `media_extensions`, `media_display`, `media_thumbnail_size`, `media_roles` |

### Настройки свойства типа `media_reference`

| `key` | Подпись | Обязательно | Значения | По умолчанию |
|---|---|---|---|---|
| `media_target` | Цель ссылки | **да** | `object`, `file`, `both` | `object` |
| `media_kinds` | Допустимые виды медиа | нет | подмножество `image`, `audio`, `video`, `document`, `other` | все |
| `media_folders` | Папки для поиска | нет | пути в хранилище | всё хранилище |
| `media_extensions` | Допустимые расширения | нет | `jpg`, `png`, `webp`, … | все |
| `media_display` | Способ показа | нет | `gallery` (карточки с миниатюрами), `list` | `gallery` |
| `media_thumbnail_size` | Размер миниатюры | нет | `small`, `medium`, `large` | `medium` |
| `media_roles` | Допустимые роли | нет | подмножество ролей из раздела 5 ADR-006 | все |

Множественность задаётся **только** `cardinality`. Отдельного типа «мультимедиа» нет — это сознательное
отличие от Metadata Menu, у которого есть `Media` и `MultiMedia` (см. обоснование в ADR-008).

### Пример: обложка с миниатюрами

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2F0
type: property
title: Cover
key: cover
label: Обложка
value_type: media_reference
media_target: object
media_kinds: [image]
media_roles: [cover]
media_display: gallery
media_thumbnail_size: medium
cardinality: 0..1
required: false
---
```

### Поведение контрола

- Миниатюра формируется через `app.vault.getResourcePath(file)` — **публичный API Obsidian**.
- Для `audio`, `video`, `document` вместо миниатюры — значок вида медиа.
- Резервное поведение: файл недоступен → значок и имя, а не пустое место.
- Работает в **нашей** модалке свойств. В стандартном автодополнении Obsidian миниатюры не появляются:
  это требует патча `EditorSuggest`, то есть недокументированных механизмов.

### Дополнительные правила валидации

| ID правила | Формулировка | Уровень |
|---|---|---|
| `value.media.target_kind` | Значение соответствует `media_target` | error |
| `value.media.kind_allowed` | Вид медиа входит в `media_kinds` | error |
| `value.media.role_allowed` | Роль входит в `media_roles` | warning |
| `value.media.in_folders` | Файл в одной из папок `media_folders` | warning |
| `value.media.extension_allowed` | Расширение входит в `media_extensions` | error |
| `value.media.file_exists` | Файл существует в хранилище | error |
| `property.media.settings_required` | У свойства типа `media_reference` заполнено `media_target` | error |
| `property.media.settings_consistent` | Поля `media_*` присутствуют только там, где имеют смысл | warning |

## 11. Условные свойства — механизм `applies_when`

> [!important] Восстановление нормативного текста
> Механизм принят записью **DL-128** (2026-10-22, требование пользователя «формат книги как
> триггер свойств»), но его нормативное описание не было сохранено в файле — на него уже ссылались
> `entities/book.md` §4, `validation/rules.md` v0.2.0 и `CHECKPOINT.md` §6.23. Раздел восстановлен
> в v0.5.0 и одновременно дополнен операцией `includes_any` (DL-139), без которой механизм
> не работает для свойств с несколькими значениями (`person.role`, `media.role`,
> `media.creation_method`).

**Бытовая аналогия.** Бланк заявления: вопрос «марка автомобиля» печатается в бланке только после
галочки «есть автомобиль». Галочка не создаёт и не уничтожает ответ — она решает, показывать ли
строку. Так же и здесь: значение поля-триггера решает, какие строки формы показать.

### 11.1. Объявление

Условие объявляется в определении свойства полем `applies_when`:

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2FA
type: property
title: Platform
key: platform
label: Площадка публикации
value_type: text
cardinality: 0..1
required: false
scope: specific
applies_when:
  property: format      # ключ свойства-триггера того же типа
  operation: equals     # equals | in_category | includes_any
  value: web_novel      # одно значение или список значений
---
```

| Поле | Подпись | Обязательно | Значения |
|---|---|---|---|
| `applies_when.property` | Свойство-условие | да | `key` свойства **того же типа** (или унаследованного) |
| `applies_when.operation` | Операция | да | `equals`, `in_category`, `includes_any` |
| `applies_when.value` | Значение | да | Строка или список строк (для перечислений — ключи значений; для `in_category` — `id` категорий) |

**Семантика операций:**

| Операция | Условие истинно, когда | Для каких свойств-триггеров |
|---|---|---|
| `equals` | Значение равно `value` (для свойства `0..N` — хотя бы один элемент равен) | одиночные и множественные |
| `in_category` | Объекту назначена категория из `value` | любой; триггер — не свойство, а назначение категории |
| `includes_any` | **Хотя бы одно** значение свойства-триггера входит в список `value` | множественные (`cardinality: 0..N`, `1..N`) |

Операция `includes_any` **добавлена 2026-10-22 (DL-139)**: род занятий человека и способ создания
изображения — множественный выбор, а условие должно срабатывать, когда выбрано любое из перечисленных
значений. Для одиночного значения `includes_any` равносилен `equals`, поэтому отдельной операции
«входит во все» (`includes_all`) в MVP нет.

### 11.2. Правила М1–М7

| ID | Правило | Смысл |
|---|---|---|
| **М1** | Условие влияет **только на показ и на проверку обязательности**, никогда — на хранение | Смена `format` с `web_novel` на `file` не удаляет введённую `platform` |
| **М2** | Значения «погасших» свойств не удаляются и не помечаются | Вернули условие — значение снова на экране. Молчаливое удаление данных запрещено (спецификация v1.0 §19) |
| **М3** | Цепочки условий запрещены: у свойства-триггера не может быть собственного `applies_when` | Иначе получаем каскад, который невозможно проверить и объяснить пользователю |
| **М4** | Список операций закрыт | В MVP: `equals`, `in_category`, `includes_any`. Расширение — через изменение метамодели, не через настройки |
| **М5** | Условие — одно на свойство и ссылается на одно свойство-триггер | Составные условия (`и`, `или`) в MVP не поддерживаются |
| **М6** | Обязательность проверяется **только когда условие выполнено** | Скрытое свойство не мешает сохранить объект; правило `value.cardinality` для него не запускается |
| **М7** | Одно свойство может обслуживать несколько групп значений: перечислите их в `value` | `known_for` объявляется один раз с `value: [athlete, scientist, …]`, а не по разу на профессию |

> [!warning] М6 и область действия
> Механизм работает в **формах плагина** (модалка создания и редактирования, карточка объекта).
> В стандартной панели свойств Obsidian все объявленные свойства видны всегда: панель рисует
> Obsidian, а не плагин. Это осознанное ограничение — оно следует из ADR-003 (отказ от патчей
> чужого интерфейса) и подтверждается исследованием
> [[../integrations/research-front-matter-title-stability|стабильности Front Matter Title]].

### 11.3. Что может быть триггером

Триггером может быть **любое** свойство подходящей формы, не только перечисление.

| Триггер | Тип | Операция | Где используется |
|---|---|---|---|
| `book.format` | перечисление, одно значение | `equals` | 10 условных свойств книги (DL-122) |
| `person.role` | перечисление, **мультивыбор** | `includes_any` | 19 условных свойств человека (DL-138) |
| `media.creation_method` | перечисление, **мультивыбор** | `includes_any` | свойства фото, скана, ИИ-генерации (DL-141) |
| `media.role` | перечисление, **мультивыбор** | `includes_any` | зарезервировано; в MVP свойств не включает |
| Назначение категории | фасет | `in_category` | зарезервировано для этапов 2+ |

**Вывод, который важно зафиксировать:** механизм один и тот же для книги и для человека. Разница
только в кратности триггера (одно значение против нескольких) и, как следствие, в операции.
Новых механизмов не потребовалось — это проверка метамодели на прочность, и она пройдена.

### 11.4. Правила валидации

| ID | Формулировка | Уровень |
|---|---|---|
| `property.applies_when.property_exists` | Свойство, на которое ссылается `applies_when`, существует в том же типе | error |
| `property.applies_when.no_chain` | У свойства-условия нет собственного `applies_when` (М3) | error |
| `property.applies_when.operation_closed` | Операция входит в закрытый список (М4) | error |
| `property.applies_when.value_present` | Поле `value` заполнено и не пусто | error |
| `property.applies_when.operation_matches_cardinality` | `includes_any` применяется только к триггеру с множественной кардинальностью | warning |

Полные формулировки — [[../validation/rules|единый реестр правил]], группа B.

## 12. Настройки отображения числовых значений (`display.*`)

Приняты записью **DL-123** (2026-10-22). Настройки объявляются в определении свойства
типа `number` и влияют **только на показ**, никогда — на хранение (тот же принцип, что и М1).

| Настройка | Подпись | Значения | По умолчанию |
|---|---|---|---|
| `display.renderer` | Способ показа | `plain`, `stars`, `progress` | `plain` |
| `display.scale_max` | Предел шкалы | число > 0 | `10` |
| `display.unit` | Единица измерения | текст: `стр.`, `мин`, `₽`, `км` | пусто |

**Пример: оценка книги.** В файле хранится `rating: 7`; в режиме `view` рисуется
`★★★★★★★☆☆☆ 7/10`. Символы звёзд в данных **не хранятся** (DL-117): их нельзя сортировать,
сравнивать и усреднять, а «звёздочка» встречается в двух кодировках (U+2B50 ⭐ и U+2605 ★) —
поиск начал бы промахиваться.

```yaml
---
type: property
key: rating
label: Оценка
value_type: number
cardinality: 0..1
display:
  renderer: stars
  scale_max: 10
---
```

Шкала **едина для всех типов объектов**: `stars` работает и у книги, и у фильма, и у проекта.
Отдельного «звёздного» типа значения нет.

| `renderer` | Как рисуется | Где уместен |
|---|---|---|
| `plain` | `480 стр.` | Объём, количество, год |
| `stars` | `★★★★★★★☆☆☆ 7/10` | Личная оценка |
| `progress` | `▓▓▓▓▓▓░░░░ 60 %` | Готовность, доля выполнения |
