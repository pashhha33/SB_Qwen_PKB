# 06. Даты и интервалы

> [!info] Статус документа
> Нормативный. Основание — [[../adr/ADR-011-enumerations-dates-lifecycle|ADR-011]] и
> [[../adr/ADR-006-system-attributes-value-types-media|ADR-006]].

## 1. Форматы хранения

| Тип значения | Формат | Пример | Точность |
|---|---|---|---|
| `date` | `YYYY-MM-DD` | `2026-10-22` | день |
| `datetime` | `YYYY-MM-DDTHH:mm` | `2026-10-22T14:35` | минута |

Правила:

- **локальное время, без смещения часового пояса** (решение пользователя, ADR-006);
- секунды не храним;
- разделитель даты и времени — латинская `T`;
- ведущие нули обязательны: `2026-03-05`, а не `2026-3-5`.

> [!warning] Известное ограничение (G-04-1)
> Локальное время без смещения нарушает хронологический порядок, если записи создаются в разных
> часовых поясах. Для личной базы в одном поясе приемлемо. Если ограничение начнёт мешать — добавим
> необязательное поле `timezone` или переход на UTC как ломающее изменение с миграцией.

## 2. Частичные даты

Неизвестная часть обозначается `00`.

| Запись | Что значит |
|---|---|
| `1928-00-00` | Известен только год |
| `1928-05-00` | Известны год и месяц |
| `1928-05-15` | Полная дата |
| `0000-00-00` | Дата неизвестна. Допустимо, но предпочтительнее оставить поле пустым |

### Правила

| № | Правило | Уровень проверки |
|---|---|---|
| П1 | Неизвестная часть не может идти после известной: `1928-00-15` недопустимо | `error`, `date.partial.no_gap` |
| П2 | `0000-00-00` допустимо только там, где поле необязательно | `warning` |
| П3 | При сравнении неизвестный компонент считается **меньше** любого известного | — (правило вычисления) |
| П4 | При проверке вхождения в диапазон частичная дата входит, если входит хотя бы один день описываемого ею множества | — (правило вычисления) |
| П5 | При отображении частичная дата показывается по своему шаблону, без нулей | — |
| П6 | Формат **не является** стандартом ISO 8601. Значение нельзя передавать внешним библиотекам разбора дат без нормализации в диапазон | — (ограничение реализации) |

### Примеры порядка при сортировке по возрастанию

```text
1928-00-00   (только год)
1928-05-00   (год и месяц)
1928-05-15   (полная дата)
1929-00-00
```

### Нормализация в диапазон

Единственная точка входа для всех вычислений — функция нормализации (мера M4 ADR-011):

| Значение | Нормализованный диапазон |
|---|---|
| `1928-00-00` | `1928-01-01` … `1928-12-31` |
| `1928-05-00` | `1928-05-01` … `1928-05-31` |
| `1928-05-15` | `1928-05-15` … `1928-05-15` |

## 3. Интервалы

| Случай | Как записывается |
|---|---|
| Закрытый интервал | `starts_on: 1928-05-00`, `ends_on: 1929-00-00` |
| Открытый интервал («по настоящее время») | `ends_on: null` |
| Одиночная дата | одно поле типа `date` или `datetime` |
| Оба конца частичные | `starts_on: 1928-00-00`, `ends_on: null` — допустимо |

### Правила

| № | Правило | Уровень |
|---|---|---|
| И1 | `starts_on` не позже `ends_on` с учётом правила П3 | `error`, `relation.period.order` / `object.period.order` |
| И2 | `ends_on: null` означает «по настоящее время» — это нормально, а не ошибка | `info`, `relation.period.open` |
| И3 | Пересечение интервалов у связей одного типа от одного субъекта по умолчанию **разрешено**. Ограничение включается полем `forbid_overlap: true` у типа отношения | **предложение, требует подтверждения** |
| И4 | Длительность не хранится, а вычисляется | — |

## 4. Шаблон вывода даты и времени

Шаблон — строка с **токенами** в квадратных скобках. Всё, что вне скобок, выводится как есть.

### 4.1. Настройки плагина

| Настройка | Что задаёт | По умолчанию |
|---|---|---|
| `date_template` | Полная дата | `[DD].[MM].[YYYY]` |
| `datetime_template` | Дата со временем | `[DD].[MM].[YYYY] [HH]:[mm]` |
| `time_template` | Время | `[HH]:[mm]` |
| `partial_year_template` | Известен только год | `[YYYY]` |
| `partial_month_template` | Известны год и месяц | `[MMMM] [YYYY]` |
| `use_relative_dates` | Показывать «сегодня», «вчера», «N дней назад» | `false` |
| `relative_threshold_days` | Порог в днях | `7` |

### 4.2. Токены

| Токен | Что подставляет | Пример для 5 мая 1928 |
|---|---|---|
| `[YYYY]` | Год, четыре цифры | `1928` |
| `[YY]` | Год, две цифры | `28` |
| `[MM]` | Месяц, две цифры | `05` |
| `[M]` | Месяц без ведущего нуля | `5` |
| `[MMMM]` | Месяц словом, именительный падеж | `май` |
| `[MMM]` | Месяц сокращённо, родительный падеж | `мая` |
| `[DD]` | День, две цифры | `05` |
| `[D]` | День без ведущего нуля | `5` |
| `[Do]` | День с русским окончанием | `5-е` |
| `[WW]` | ISO-номер недели | `18` |
| `[HH]` | Часы, 24 часа | `14` |
| `[hh]` | Часы, 12 часов | `02` |
| `[mm]` | Минуты | `35` |
| `[A]` | Половина дня словами | `дня` |
| `[ddd]` | День недели сокращённо | `сб` |
| `[dddd]` | День недели полностью | `суббота` |
| `[N]` | Число дней (только в шаблонах относительных дат) | `3` |

Примеры шаблонов и результата:

| Шаблон | Результат |
|---|---|
| `[DD].[MM].[YYYY]` | `05.05.1928` |
| `[D] [MMMM] [YYYY] года` | `5 май 1928 года` |
| `[YYYY]-[MM]-[DD]T[HH]:[mm]` | `1928-05-05T14:35` |
| `[ddd], [Do] [MMM] [YYYY]` | `сб, 5-е мая 1928` |

### 4.3. Пресеты

Выбираются одной кнопкой, потом можно править вручную.

| Пресет | `date_template` | `datetime_template` |
|---|---|---|
| Русская дата (**по умолчанию**) | `[DD].[MM].[YYYY]` | `[DD].[MM].[YYYY] [HH]:[mm]` |
| ISO | `[YYYY]-[MM]-[DD]` | `[YYYY]-[MM]-[DD]T[HH]:[mm]` |
| Словесная | `[D] [MMMM] [YYYY]` | `[D] [MMMM] [YYYY], [HH]:[mm]` |
| Короткая | `[DD].[MM].[YY]` | `[DD].[MM].[YY] [HH]:[mm]` |
| Американская | `[MM]/[DD]/[YYYY]` | `[MM]/[DD]/[YYYY] [hh]:[mm] [A]` |

### 4.4. Относительные даты

Применяются, когда `use_relative_dates: true` и дата в пределах `relative_threshold_days`.

| Случай | Шаблон по умолчанию | Пример |
|---|---|---|
| Сегодня | `сегодня, [HH]:[mm]` | `сегодня, 14:35` |
| Вчера | `вчера, [HH]:[mm]` | `вчера, 19:02` |
| Завтра | `завтра, [HH]:[mm]` | `завтра, 10:00` |
| N дней назад | `[N] дн. назад` | `3 дн. назад` |
| Через N дней | `через [N] дн.` | `через 5 дн.` |
| Вне порога | обычный `date_template` | `12.03.2026` |

> [!note] Техническое замечание для Фазы 5
> Русские формы числительных требуют склонения: «1 день», «2 дня», «5 дней». Это реализуется отдельной
> функцией склонения, а не подбором шаблона (мера M1 ADR-011).

### 4.5. Правила поведения шаблона

| № | Правило |
|---|---|
| Ш1 | Неизвестный токен показывается как есть, в квадратных скобках, и даёт `warning` в настройках. Никакого молчаливого мусора |
| Ш2 | Шаблон применяется **только к отображению**. В файлах всегда канонический формат |
| Ш3 | Один шаблон действует во всех наших представлениях: модалка свойств, таблицы, карточки, блок связей, диагностика. В стандартной панели свойств Obsidian формат не подменяется |
| Ш4 | Шаблон проверяется при сохранении настройки: пустая строка и строка без токенов допустимы, неизвестный токен — предупреждение |
| Ш5 | Частичные даты используют свои шаблоны, а не основной `date_template` |

## 5. Системные даты

| Поле | Подпись | Кто заполняет | Правила |
|---|---|---|---|
| `created_at` | Создан | плагин при создании | Не меняется после создания (инвариант И5) |
| `updated_at` | Изменён | плагин при каждом сохранении | ≥ `created_at`; обновляется только если содержание действительно изменилось (мера M4 ADR-006) |

Если поля отсутствуют (заметка создана не плагином), плагин **дописывает** их при первом сохранении
через свою команду и выдаёт `warning` — не `error` и не молча.

## 6. Правила валидации

| ID правила | Формулировка | Уровень |
|---|---|---|
| `date.format` | Значение соответствует `YYYY-MM-DD` или частичному варианту с `00` | error |
| `datetime.format` | Значение соответствует `YYYY-MM-DDTHH:mm` | error |
| `date.partial.no_gap` | Неизвестный компонент не идёт после известного | error |
| `date.partial.unknown_only_zero` | Неизвестный компонент записан как `00`, а не иным способом | error |
| `date.range.valid` | День и месяц входят в допустимый диапазон для указанного года (с учётом високосных) | error |
| `period.order` | `starts_on` не позже `ends_on` | error |
| `period.open_end` | `ends_on: null` трактуется как открытый период | info |
| `period.overlap` | При `forbid_overlap: true` интервалы не пересекаются | error |
| `datetime.no_seconds` | Время хранится с точностью до минут, секунды отсутствуют | warning |
| `display_template.tokens_known` | Все токены шаблона известны | warning |
| `display_template.not_empty_on_resolve` | Результат применения шаблона не пуст | warning |

## 7. Примеры

### Объект с полным набором дат

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2K0
type: project
title: Kitchen renovation
aliases:
  - Ремонт кухни
created_at: 2026-03-01T09:12
updated_at: 2026-10-22T14:35
status: active
starts_on: 2026-03-01
ends_on: null          # по настоящее время
---
```

### Связь с частичными датами

```json
{"id":"01J8Z6M4K2Q7V9X3N5B0C1D2K1","type":"relation","title":"Writing of The Master and Margarita","subject":"01J8Z6M4K2Q7V9X3N5B0C1D2F3","relation_type":"01J8Z6M4K2Q7V9X3N5B0C1D2G0","object":"01J8Z6M4K2Q7V9X3N5B0C1D2EF","origin_property":null,"role":null,"order":null,"starts_on":"1928-00-00","ends_on":"1940-03-00","description":"Начало работы известно по году, окончание — по месяцу.","created_at":"2026-10-22T14:35","updated_at":"2026-10-22T14:35"}
```

Показ при шаблоне по умолчанию: `starts_on` → «1928», `ends_on` → «март 1940».

### Некорректные примеры

| Значение | Нарушенное правило | Сообщение пользователю |
|---|---|---|
| `1928-00-15` | `date.partial.no_gap` | «День указан, но месяц неизвестен. Так не бывает: неизвестная часть даты должна идти в конце» |
| `22.10.2026` | `date.format` | «Дата должна быть в формате ГГГГ-ММ-ДД, например 2026-10-22. Формат показа настраивается отдельно» |
| `2026-10-22T14:35:07` | `datetime.no_seconds` | «Секунды не хранятся. Значение будет округлено до минут» |
| `starts_on: 1940-00-00`, `ends_on: 1928-00-00` | `period.order` | «Дата начала позже даты окончания» |
