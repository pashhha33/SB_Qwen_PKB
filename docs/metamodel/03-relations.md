# 03. Связи

> [!info] Статус документа
> Нормативный. Основание — [[../adr/ADR-009-relations-model|ADR-009]] (модель) и
> [[../adr/ADR-010-relation-storage|ADR-010]] (хранение), приняты 2026-10-22.
> Карточки отдельных связей лежат в `relations/`, здесь — сводный реестр и общие правила.

## 1. Два способа хранить связь

Способ **объявляется в определении свойства** полем `link_mode`, а не выбирается «по ситуации».

| Значение | Где хранится | Когда применять | Видно в графе Obsidian |
|---|---|---|---|
| `direct` | Ссылка в поле самого объекта (frontmatter) | У связи нет собственных данных | **Да** |
| `reified` | Объект `relation` в `.sb/relations/relations.jsonl` | У связи есть собственные данные: роль, порядок, период, описание | Нет |

> **Критерий выбора:** у связи нужны собственные данные → `reified`. Иначе → `direct`.

**Побочный эффект, который стоит знать:** в графе Obsidian будут видны только `direct`-связи.
Реифицированные связи показывает наш собственный типизированный граф (мера M6 ADR-010) —
и он умеет больше: название типа на ребре и фильтр по типу.

### Пример объявления свойства

```yaml
# простая ссылка
key: publisher
label: Издательство
value_type: object_reference
target_types: ["[[OBJECT_TYPE-….md|Организация]]"]
cardinality: 0..1
link_mode: direct

# связь с периодом
key: employed_by
label: Работает в
value_type: object_reference
target_types: ["[[OBJECT_TYPE-….md|Организация]]"]
cardinality: 0..N
link_mode: reified
relation_type: "[[RELATION_TYPE-….md|Трудоустройство]]"
```

## 2. Привязка связи к свойству

| Случай | `origin_property` | Где показывается |
|---|---|---|
| Связь создана из объявления свойства с `link_mode: reified` | заполнено | В контроле **этого** свойства и нигде больше |
| Связь создана сама по себе (свободно стоящая) | пусто | В общем блоке связей объекта с пометкой «без свойства» |

**Зачем это нужно.** Без `origin_property` два свойства одного типа, использующие один тип отношения,
видели бы связи друг друга. Пример: у книги свойства `author` и `editor`, оба на типе отношения
«Участие» — в поле «Автор» оказался бы редактор.

## 3. Тип отношения: состав полей

```yaml
---
id: 01J8Z6M4K2Q7V9X3N5B0C1D2G0
type: relation_type
title: Authorship
aliases:
  - Authorship
created_at: 2026-10-22T14:35
updated_at: 2026-10-22T14:35

key: authorship
label: Авторство
forward_label: автор
reverse_label: автор произведения
direction: directed

subject_to_object: 1..N
object_to_subject: 0..N
uniqueness_rule: triple

allowed_subject_types:
  - "[[OBJECT_TYPE-….md|Книга]]"
allowed_object_types:
  - "[[OBJECT_TYPE-….md|Человек]]"
suggested_subject_types: []
suggested_object_types: []

definition: Authorship of a written work.
---
```

| Поле | Подпись | Тип значения | Обязательность | Значения по умолчанию |
|---|---|---|---|---|
| `key` | Ключ | `text` | да | — |
| `label` | Подпись | `text` | да | — |
| `forward_label` | Прямое название | `text` | **да** | — |
| `reverse_label` | Обратное название | `text` | **да** | — |
| `direction` | Направление | enum | да | `directed` |
| `subject_to_object` | Кардинальность от субъекта | enum | да | `0..N` |
| `object_to_subject` | Кардинальность от объекта | enum | да | `0..N` |
| `uniqueness_rule` | Правило уникальности | enum | да | `triple` |
| `allowed_subject_types` | Допустимые типы субъекта | → `object_type` | нет | пусто = ограничений нет |
| `allowed_object_types` | Допустимые типы объекта | → `object_type` | нет | пусто = ограничений нет |
| `suggested_subject_types` | Предпочтительные типы субъекта | → `object_type` | нет | пусто |
| `suggested_object_types` | Предпочтительные типы объекта | → `object_type` | нет | пусто |
| `definition` | Определение | `text` | нет | — |

### Как читаются роли

| Направление | Чтение |
|---|---|
| Прямое | `субъект — forward_label → объект`. Пример: «Книга — автор → Человек» |
| Обратное | `объект — reverse_label → субъект`. Пример: «Человек — автор произведения → Книга» |

Оба поля — свободный текст на русском, оба обязательны. Автоматическое образование одного из другого
**отклонено**: правила русского языка слишком разнообразны («автор» → «автор произведения»,
но «владелец» → «владеет»).

### Направление

| Значение | Подпись | Что значит | Хранение |
|---|---|---|---|
| `directed` | Направленное | Стороны неравноправны | Как обычно |
| `symmetric` | Симметричное | Читается одинаково в обе стороны: «супруг», «синоним», «коллега» | **Один раз**, обратная сторона вычисляется |

У симметричного типа `forward_label` и `reverse_label` должны совпадать, иначе `warning`.

### Кардинальность с двух сторон

| Поле | Что ограничивает | Пример для «Авторство» |
|---|---|---|
| `subject_to_object` | Сколько объектов у одного субъекта | `1..N` — у книги минимум один автор |
| `object_to_subject` | Сколько субъектов у одного объекта | `0..N` — у человека может не быть книг |

### Правило уникальности

| Значение | Что считается дублем |
|---|---|
| `pair` | Пара «субъект — объект»: между ними вообще не может быть двух связей |
| **`triple`** (по умолчанию) | Тройка «субъект — тип отношения — объект»: «автор» и «редактор» между теми же объектами допустимы |
| `none` | Ограничений нет |

### Допустимые против предпочтительных

| Поле | Что делает | Нарушение |
|---|---|---|
| `allowed_subject_types`, `allowed_object_types` | Жёсткое ограничение | **`error`**, значение не принимается |
| `suggested_subject_types`, `suggested_object_types` | Порядок вариантов и предвыбор в модалке | Ничего, максимум `info` |

`suggested_*` должен быть подмножеством `allowed_*`, если заданы оба, иначе `warning`.

> [!note] Семантика в отношении потомков и абстрактных типов (DL-208, DL-209)
> Указание типа в `allowed_subject_types` / `allowed_object_types` (и в `suggested_*`) покрывает
> **всех его потомков**; абстрактный тип (`work`, `activity`…) разрешён и означает «любой
> неабстрактный потомок» (например, `authorship → work` покрывает книгу, главу, стихотворение).
> Норма — [[07-hierarchy|`07-hierarchy.md`]] §5, §7.

## 4. Экземпляр связи: состав полей

```json
{
  "id": "01J8Z6M4K2Q7V9X3N5B0C1D2G1",
  "type": "relation",
  "title": "Bulgakov authored The Master and Margarita",
  "subject": "01J8Z6M4K2Q7V9X3N5B0C1D2F3",
  "relation_type": "01J8Z6M4K2Q7V9X3N5B0C1D2G0",
  "object": "01J8Z6M4K2Q7V9X3N5B0C1D2EF",
  "origin_property": "01J8Z6M4K2Q7V9X3N5B0C1D2F0",
  "role": "автор",
  "order": 1,
  "starts_on": "1928-01-01",
  "ends_on": null,
  "description": null,
  "created_at": "2026-10-22T14:35",
  "updated_at": "2026-10-22T14:35"
}
```

| Поле | Подпись | Тип значения | Обязательность | Статус |
|---|---|---|---|---|
| `id` | — | ULID | **да** | системное |
| `type` | Тип объекта | `relation` | **да** | системное |
| `title` | Название | `text` | **да** | системное; нужно для графа и списка связей |
| `subject` | Субъект | `id` объекта | **да** | ядро |
| `relation_type` | Тип отношения | `id` типа отношения | **да** | ядро |
| `object` | Объект | `id` объекта | **да** | ядро |
| `origin_property` | Порождающее свойство | `id` свойства | нет | ядро; пусто = свободно стоящая связь |
| `role` | Роль в этой связи | `text` | нет | ядро; уточнение сверх `forward_label`, например «соавтор» |
| `order` | Порядок | `number` | нет | ядро |
| `starts_on` | Дата начала | `date` | нет | ядро |
| `ends_on` | Дата окончания | `date` | нет | ядро; `null` = по настоящее время |
| `description` | Описание | `text` | нет | ядро; **одна строка**, не заметка |
| `created_at` | Создан | `datetime` | **да** | системное |
| `updated_at` | Изменён | `datetime` | **да** | системное |
| `is_primary` | Основное | `boolean` | нет | этап 2 |
| `source` | Источник | ссылка | нет | этап 2 |
| `context` | Контекст | — | — | этап 2, семантика не определена |

### Системные атрибуты у связи — сокращённый набор

| Атрибут | У экземпляра объекта | У связи |
|---|---|---|
| `id`, `type`, `title`, `created_at`, `updated_at` | обязательны | **обязательны** |
| `aliases` | инвариант `aliases[0] == title` | **не применяется** — на связь нельзя сослаться wikilink-ом |
| `categories`, `tags` | по правилам классификации | **не применяются** |

## 5. Где хранятся связи

| Что | Где | Формат |
|---|---|---|
| `direct`-связи | frontmatter объекта | wikilink |
| `reified`-связи | `.sb/relations/relations.jsonl` | **одна строка JSON на связь** |
| Архив связей, затронутых удалением определения свойства | `.sb/relations/archive/` | то же |

Правила формата: ссылки — **голые `id`**; пустые значения — `null`, а не пропуск ключа; кодировка UTF-8
без BOM; конец строки LF; порядок строк не значим (порядок связей задаёт поле `order`);
формат описан JSON Schema `schema/relation.schema.json`.

> [!danger] `.sb/relations/` — основные данные, не производные
> В отличие от `.sb/cache/`, хранилище связей невозможно восстановить из заметок. Его потеря — потеря данных.
> Папка `.sb/` подлежит резервному копированию вместе с заметками.

## 6. Каскадное поведение

| Ситуация | Поведение |
|---|---|
| Удаление объекта | Его связи **удаляются** |
| Удаление определения свойства | Плагин **предупреждает**, показывает число затронутых связей и предлагает: архивировать или очистить `origin_property` (связь станет свободно стоящей и не потеряется) |
| Удаление определения типа отношения | **Запрещено**, пока есть связи |

## 7. Обратная сторона

Не хранится, **вычисляется**. В форме объекта показывается блок «Связан с этим объектом» — только для чтения.
Чтобы изменить связь, пользователь идёт к исходному объекту.

## 8. Реестр типов отношений

### Ядро MVP

| Тип отношения | `key` | `TYPE_PREFIX` | Субъект → Объект | Направление | Кардинальности | Уникальность | `link_mode` у свойства | Карточка |
|---|---|---|---|---|---|---|---|---|
| Авторство | `authorship` | `RELATION_TYPE` | `book` → `person` | `directed` | `1..N` / `0..N` | `triple` | `direct` | [[relations/rel_authorship]] |
| Владение | `ownership` | `RELATION_TYPE` | `project` → `person` | `directed` | `1` / `0..N` | `triple` | `direct` | [[relations/rel_ownership]] |
| Часть целого | `part_of` | `RELATION_TYPE` | `chapter` → `work`, `episode` → `series` | `directed` | `0..1` / `0..N` | `triple` | `reified` (нужен `order`) | [[relations/rel_part_of]] |
| Связано с | `related_to` | `RELATION_TYPE` | `knowledge` → `knowledge` | `symmetric` | `0..N` / `0..N` | `triple` | `direct` | [[relations/rel_related_to]] |

#### `contains` — «содержит» (DL-125, 2026-10-22)

| Поле | Значение |
| --- | --- |
| `relation_type` | `contains` |
| `direction` | `directed` |
| `link_mode` | **`reified`** — связь с собственными свойствами (`order`, `role`) |
| `subject_to_object` | `0..n` (произведение содержит много частей) |
| `object_to_subject` | **`0..1`** (часть входит не более чем в одно произведение) |
| `uniqueness_rule` | `triple` |
| `forward_label` / `reverse_label` | «содержит» / «входит в» |
| `allowed_subject_types` | `book`, `work`, `media`, `project`, `activity`, `collection` |
| `allowed_object_types` | `chapter`, `book`, `work`, `media`, `media_asset` |
| `required` | нет (но у `chapter` фактически обязательна — правило `chapter.contains.required`) |

**Почему `reified`:** главе нужен **порядковый номер** внутри произведения
(локальное свойство `order`) и, при желании, роль (`role`: «глава»,
«пролог», «эпилог», «приложение»). Прямой ссылкой это не выразить.

**Обратная сторона — `part_of`.** `contains` и `part_of` — две стороны одной
семантики. Чтобы не хранить одну связь дважды, **хранится только `contains`**;
`part_of` объявлена обратной (правило `relation.contains.single_record`): запрос «входит в» разрешается
чтением той же записи в обратном направлении.

**Карточка:** `relations/rel_contains.md`.

## Этап 2

| Тип отношения | `key` | Зачем | Почему не в MVP |
|---|---|---|---|
| Трудоустройство | `employment` | Период работы в организации | Нужен тип `organization` |
| Источником является | `sourced_from` | Ссылка на источник сведения | Нужны типы группы «Источник» |
| Входит в коллекцию | `member_of` | Книга в серии, трек в альбоме | Нужен тип `collection` |
| Изображает / иллюстрирует | `depicts` | Связь объекта `media` с объектом | Ждёт уточнений пользователя по обёртке (DL-088) |
| Соавторство | `co_authorship` | Несколько авторов с ролями | Работает через `authorship` + поле `role` |
| Конфликтует с | `conflicts_with` | Пример свободно стоящей связи | Не нужен для критерия стабильного ядра |
