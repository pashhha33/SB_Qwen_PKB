## Что это

**Бутстрап метамодели (A2 часть 2, DL-257)** — последний крупный кусок под-батча A2.

Метамодель описывает саму себя: чтобы прочитать из хранилища определения типов, нужен тип
`object_type`, а его определение — само такая же заметка («курица и яйцо»). Решение принято
давно (ADR-004, главный риск этапа A в `phases.md` §4): определения системных типов
поставляются **внутри плагина как данные** и выгружаются в хранилище при первом запуске.

Что делает плагин 0.4.0 при загрузке:

1. Проверяет, есть ли в `Metamodel/ObjectTypes/` семь семенных заметок
   `OBJECT_TYPE-{фиксированный ULID}.md` — по одной на системный тип: `object_type`,
   `property`, `relation_type`, `relation`, `taxonomy`, `facet`, `category`
   (объём семени — ваш ответ **F5-10 = Б**, DL-250; `property_type` не сеется — он
   абстрактный и без карточки, ADR-004).
2. Чего нет — создаёт (папка создаётся автоматически). Что уже есть — **не трогает**:
   ваши правки определений остаются в силе (источник истины — хранилище, ADR-002).
   Повторный запуск ничего не дублирует (идемпотентность — ваш ответ **F5-9 = А**).
3. Перечитывает реестр — и Notice загрузки теперь показывает
   **«Second Brain 0.4.0: загружен (типов в реестре: 7)»** вместо 0.
4. Отдельный Notice «бутстрап … создано 7» — только при первом запуске (или если вы
   удалили часть определений); итоги всегда пишутся в журнал (`show-log`, область
   `bootstrap`).

**Фиксированные ULID (F5-9 = А).** `id` семи системных типов — «известные» константы,
одинаковые во всех хранилищах (например, `object_type` — `01M5K0XB00HX9XWND1C4WYZEYW`).
Рецепт воспроизводим и закреплён тестом: временная часть — дата утверждения метамодели
1.0.0 (2026-10-23T00:00:00Z), «случайная» часть — SHA-256 от строки
`second-brain/system-type/{type_key}`. Поэтому документация и примеры могут ссылаться на
реальные id системных типов. Формально это исключение из правила «`id` не переиспользуется» —
оно зафиксировано примечанием в **ADR-001 (ревизия 0.2.1)**, как и предусматривал DL-250:
константы никогда не выдавались другим объектам, так что переиспользования нет.

**Семенные заметки** — обычный Markdown c frontmatter (тот же формат, что создаёт команда
`create-object-type`): `title` = английский ключ, `label` — русская подпись из реестра
`02-entities` §3, `abstract: false`, `lifecycle: standard`, все семь — корни дерева типов.
В теле — короткая справка о назначении типа и предупреждение не менять `id` и имя файла.
Содержимое статично (байт-стабильно): LF, без BOM, без токенов Templater (DL-190).

**Отказоустойчивость:** если одно определение не удалось записать (например, папка занята),
остальные шесть создадутся, ошибка уйдёт в журнал, а в отчёте будет `failed: 1`.

Версии: плагин **0.3.2 → 0.4.0** (MINOR — новая функциональность); метамодель **не менялась
(1.2.0)** — CHANGELOG **[1.2.2]** (учётная запись: реализованы ранее принятые решения).
Тесты: **143 → 157** (+14).

   - Notice **«Second Brain 0.4.0: загружен (типов в реестре: 7)»** (было 0 в прошлый раз).
2. В проводнике файлов слева появилась папка **`Metamodel/ObjectTypes/`** с семью заметками
   `OBJECT_TYPE-01M5K0XB00….md`. Откройте любую (например, `object_type`): frontmatter с
   `id`, `label: Тип объекта`, в теле — справка. Свойство `label` можно поменять — плагин
   подхватит при следующей загрузке (а `id` и имя файла менять не нужно).
3. Перезагрузите плагин ещё раз: Notice бутстрапа **не повторяется** (идемпотентность),
   Notice загрузки по-прежнему «типов в реестре: 7». В журнале (`Ctrl+P` → show-log)
   при включённом уровне «отладка» видна запись `bootstrap … все 7 определений уже
   существуют — пропуск`.
4. Проверка рядом с семенами: `Ctrl+P` → **Second Brain: Создать тип объекта
   (create-object-type)** → введите пробный тип (например, key `test_type`, подпись
   «Тест», префикс `TEST_TYPE`) — создаётся восьмая заметка в той же папке; после
   проверки удалите её (реестр перечитается при следующей загрузке).
