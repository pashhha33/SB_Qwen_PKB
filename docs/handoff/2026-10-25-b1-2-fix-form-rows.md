## Что произошло (диагноз вашего отчёта)

Вы увидели: у «Формат» — рабочий список, у остальных свойств («Площадка», «Оценка», …) —
только подпись, ввести ничего нельзя. Причина — дефект компонента формы (0.8.0):

- строки ввода **одиночных** полей (кардинальность `0..1`/`1`, кроме перечислений и
  логических) рисовались циклом по списку текущих значений; у незаполненного свойства
  список пуст — цикл не рисует **ничего**, а кнопка «+ добавить значение» предусмотрена
  только для множественных полей;
- `format` работал, потому что перечисление рисуется отдельной веткой — выпадающий
  список показывается всегда.

Ядро (object-service: видимость условных полей, уровень 1, запись) не затронуто — дефект
чисто компонентный. Автотесты (299) его не поймали: компонент не рендерится в тестах
(граница B1.2-2 — UI проверяется вручную); **ваша ручная проверка сработала как задумано**.

## Исправление (0.8.1)

Логика «одиночное поле всегда имеет ровно одну строку ввода (пустую, если значения нет)»
вынесена из компонента в ядро — `initialEditRows(values, multiple)` в `object-service`
(регрессионная защита по уроку DL-255 «дефект → контракт-тест»: 4 новых юнит-теста);
компонент инициализируется через хелпер + страховка в шаблоне. Множественные поля без
значений — как и задумано: ноль строк + кнопка «+ добавить значение».

Тесты **299 → 303**; матрица TZ ×5 — 303/303; typecheck/build — без предупреждений;
корневой прогон — 74 OK; check:docs — 0 разрывов.
