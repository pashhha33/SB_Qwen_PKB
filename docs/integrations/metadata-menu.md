# Интеграция: Metadata Menu

> [!important] Решение одной строкой
> **Референс, не зависимость** (DL-018; ADR-006, ADR-008; карточка — DL-196). Главный технический
> ориентир для типа свойства `media_reference` и для форм управляемого ввода.

## Что это и зачем рассматривали

Metadata Menu — сторонний плагин управления метаданными заметок: типы полей, формы ввода,
справочники значений, «fileClass»-заметки как схемы. Для нас — ориентир, на котором проверялись
решения ADR-006 (тип `media`, миниатюры в **собственных** формах) и ADR-008 (тип свойства
`media_reference`: у Metadata Menu есть поля `Media` и `MultiMedia` с настройками «папки с медиа»,
«размер встраивания», «список или карточки/галерея»).

## Что он умеет (факты, не догадки)

- Версия / дата проверки: **0.8.12** (релиз 2026-02-11); **проверено 2026-10-23**
  (github.com/mdelobelle/metadatamenu: 767 коммитов, 154 тега, поддержка продолжается —
  свежие правки рендеринга и bulk-edit).
- Статус проекта: автор (mdelobelle) развивает **преемника** — плагин [[fileclass|Fileclass]] (2026)
  на базовом Bases; в документации Fileclass прямо сказано: «преемник Metadata Menu (тот же автор);
  если вы полагаетесь на инлайновые поля Dataview (`key:: value`) — оставайтесь на Metadata Menu».
- Есть ли публичный API: частично (API плагина для полей и заметок); мы его не используем.
- Что именно доступно (по документации):
  - типы полей: Input, Number, Boolean, Select, Multi, Date, DateTime, Time, File, MultiFile,
    **Media**, **MultiMedia**, Lookup, Link, MultiLink, Formula, Canvas Group и др.;
  - управляемый ввод: контекстные меню у полей, модалка «note fields modal», индикаторы
    в режиме чтения; **миниатюры медиа показываются в собственных формах плагина**;
  - схемы: fileClass-заметки (список полей с типами и настройками), привязка по тегу/полю `fileClass`;
  - исторически значения полей читаются и из **инлайновых полей Dataview** (`key:: value`) —
    зависимость от Dataview, от которой новый Fileclass отказался.
- Источники: <https://github.com/mdelobelle/metadatamenu>,
  <https://mdelobelle.github.io/metadatamenu/>.

## Что мы взяли и где осознанно разошлись

| Их решение | Наше решение |
|---|---|
| Поля `Media`/`MultiMedia` — отдельные типы | Один тип `media_reference`; множественность — **только** `cardinality` (ADR-006/008, отмена типов «Список») |
| Настройки медиа-поля: папки, размер встраивания, список/галерея | Семь настроек `media_*`: `media_target`, `media_kinds`, `media_folders`, `media_extensions`, `media_display`, `media_thumbnail_size`, `media_roles` (ADR-008) |
| Миниатюры в собственных формах | Так же: миниатюры только в **нашей** модалке, через публичный `getResourcePath()`; в стандартном автодополнении Obsidian миниатюр не будет (патч `EditorSuggest` запрещён) |
| Инлайновые поля Dataview как источник данных | Только frontmatter (ADR-002); Dataview отклонён ([[dataview\|карточка]]) |
| Схемы fileClass привязкой по тегу | Явный системный атрибут `type` + ULID-идентификация (ADR-001/006) |

## Варианты

### Вариант 1 — использовать как зависимость
- Плюсы: готовые формы и типы полей без своего UI.
- Минусы: их модель полей конкурирует с нашей метамоделью (два источника правды); связь значений
  с Dataview; автор переводит развитие в Fileclass. **Отклонён.**

### Вариант 2 — реализовать самим (принят)
- Наши контролы свойств в модалке и панели объекта (В7) повторяют полезное из их UX,
  но работают от нашей схемы (`property`, `applies_when`, `display.*`).

### Вариант 3 — отказаться без изучения
- Минусы: потеря ориентира, на котором уже проверен ADR-008. **Отклонён.**

## Оценка

| Критерий | Оценка | Комментарий |
|---|---|---|
| Полезность для задач пользователя | Как зависимость — отрицательная | Конфликт схем; как референс — высокая |
| Совместимость с нашей метамоделью | Низкая (как зависимость) | Своя модель полей и привязки классов |
| Стабильность API | Средняя | Поддерживается (0.8.12, 2026-02), но фокус автора сместился в Fileclass |
| Зависимость от чужого плагина | Высокая (была бы) | Исторически связан с Dataview |
| Сложность реализации для новичка | — | Не реализуем: только читаем опыт |

## Риск и способ защиты метамодели

| Риск | Вероятность | Последствие | Мера защиты |
|---|---|---|---|
| Пользователь включает Metadata Menu параллельно | Низкая | Оба пишут frontmatter; их поля вне нашей схемы | Наша валидация помечает поля вне схемы; рекомендация в документации: не смешивать на одних типах; `id`/`type` они не трогают (И1–И3) |
| Ориентир «уедет»: автор развивает Fileclass | Уже происходит | Ссылки на MDM устаревают | Карточка фиксирует версии и даты; преемник описан в [[fileclass|карточке Fileclass]] |

## Решение

**Отказаться как от зависимости; использовать как референс.** Подтверждено ранее: DL-018,
ADR-006 (миниатюры в собственных формах — их практика подтвердила наш путь), ADR-008
(`media_reference` сверен с `Media`/`MultiMedia`). Карточка создана в партии 2 шага 8d
(DL-196), 2026-10-23.
