# Интеграция: Front Matter Title

> [!important] Решение одной строкой
> **Необязательная рекомендуемая интеграция** (ADR-001, уровень 2 стратегии читаемости).
> Без неё плагин работает полностью. Модуль `front-matter-title-adapter` — обнаружение,
> рекомендация, мягкий отказ; никакого управления чужим плагином.

## Что это и зачем нам

Front Matter Title (FMT) — сторонний плагин, который **подменяет отображаемое название** заметки
в интерфейсе Obsidian (проводник, вкладки, поиск, автодополнение ссылок) значением поля
frontmatter — в нашем случае `title`.

Second Brain именует файлы технически (`{TYPE_PREFIX}-{ULID}.md`, ADR-001): стабильно, но
нечитаемо. Уровень 1 (инвариант И4 `aliases[0] == title`) штатно покрывает автодополнение ссылок
и быстрый переключатель. FMT закрывает уровень 2 — читаемые названия в остальном интерфейсе
**без собственных патчей внутренностей Obsidian** (уровень 3 — свой слой подмены — отклонён
ADR-001 и вынесен за MVP).

## Что он умеет (факты, не догадки)

- Версия / дата проверки: **4.2.1** (релиз 2026-08-28). Источник — наше исследование
  [[research-front-matter-title-stability|«Насколько часто ломается Front Matter Title»]]
  от **2026-10-22**; для карточки отдельная проверка не проводилась — исследование покрывает
  текущий релиз.
- Репозиторий: <https://github.com/snezhig/obsidian-front-matter-title>. Поддерживается активно:
  четыре релиза за пять месяцев, 793 коммита, 237 модульных и 16 сквозных тестов (прогнаны
  на реальном Obsidian 1.12.7).
- Есть ли публичный API: **нет** (и не нужен: мы его не управляем, только обнаруживаем).
- Ключевые факты из исследования:
  - патчит около **10 недокументированных внутренностей** Obsidian (через FunctionReplacer) —
    подтверждено самим автором;
  - два инцидента «белого экрана»: #233 (2024-10, Obsidian 1.7.x) и #251 (~2025);
  - с **2026-06-23** (коммит 2b4d6e5) — режим **мягкого отказа** (fail-soft): несовпадение
    сигнатур внутренних API больше не обрушивает загрузку;
  - на 2026-10-22 — **10 открытых проблем из 179**; характер — «в отдельных местах показывается
    имя файла вместо названия» (#297 базовый сценарий, #294 откат после перерисовки,
    #277 вкладка при открытии из поиска).

## Варианты

### Вариант 1 — рекомендуемая необязательная интеграция (принят)
- Плюсы: читаемые названия в проводнике, вкладках и поиске без наших патчей; плагин жив,
  с июня 2026 деградирует мягко; ставить или нет — решает пользователь.
- Минусы: качество отображения вне нашего контроля; точечные сбои после обновлений Obsidian возможны.
- Риски: закрыты мерами M1–M7 ADR-001 (ниже).

### Вариант 2 — не использовать вовсе
- Плюсы: ноль внешних рисков.
- Минусы: технические имена файлов в интерфейсе — главная UX-претензия к модели ADR-001;
  уровень 1 (aliases) покрывает только автодополнение и переключатель.

### Вариант 3 — собственный слой подмены (раздел 17 черновика v1.1)
- Плюсы: полный контроль.
- Минусы: пришлось бы патчить те же ~10 недокументированных внутренностей и нести стоимость
  поддержки FMT на себе.
- **Отклонён ADR-001**, вне MVP (`title-substitution-layer` — «не реализуем», `09-modules.md` §6).

## Оценка

| Критерий | Оценка | Комментарий |
|---|---|---|
| Полезность для задач пользователя | Высокая | Читаемые названия в проводнике, вкладках, поиске |
| Совместимость с нашей метамоделью | Высокая | Читает `title` из frontmatter — наш системный атрибут; в данные не пишет |
| Стабильность API | Низкая | Патчит ~10 недокументированных внутренностей; два «белых экрана»; с 2026-06 — мягкий отказ |
| Зависимость от чужого плагина | Нет для нас | Необязателен: без него работает всё, уровень 1 остаётся |
| Сложность реализации для новичка | Низкая | Адаптер = обнаружение + уведомление + документация; никакого управления |

## Риск и способ защиты метамодели

Меры — M1–M7 из ADR-001 (сводно; полный текст в ADR и исследовании):

| Риск | Вероятность | Последствие | Мера защиты |
|---|---|---|---|
| FMT сломается в обновлении Obsidian | Средняя (раз в 1–2 года полный отказ; хронический хвост мелочей) | Названия откатятся к именам файлов; в худшем случае «белый экран» чужого плагина | **M1** — отображаемое название никогда не участвует в разрешении ссылок (только `id` и канонический путь); **M4** — резервное поведение: показывать имя файла, а не пустоту; с 2026-06 сам FMT деградирует мягким отказом |
| FMT не установлен | Высокая (выбор пользователя) | Технические имена в интерфейсе | Уровень 1 работает штатно (И4 `aliases[0] == title`); псевдоним в канонической ссылке всегда (DL-186); **M6** — честная документация границ поддержки |
| Названия показываются не везде корректно | Высокая (10 открытых проблем) | Косметика | **M7** — регрессионная проверка отображения после обновлений Obsidian (ручной чек-лист); ничего не обещаем сверх документированного (M6) |
| Конфликт с нашими `aliases` | Низкая | — | FMT только читает frontmatter; инвариант И4 поддерживает наш плагин |
| Сбой адаптера роняет наш плагин | Низкая | — | **M3** — каждый адаптер изолирован, сбой одного не ломает остальные (правило М3 `09-modules`) |

## Решение

**Использовать как необязательную рекомендуемую интеграцию.** Уровень 2 стратегии читаемости
ADR-001: данные (И4 + псевдоним в ссылках, DL-186) — обязательный минимум; FMT — рекомендуемое
дополнение; собственный слой подмены — вне MVP. Модуль `front-matter-title-adapter`
(`09-modules.md`, этап A): обнаруживает наличие плагина, при отсутствии показывает рекомендацию,
при сбое деградирует молча до имени файла (M4). Подтверждено пользователем: ADR-001 (2026-10-22);
карточка создана по итогам под-шага 8d, партия 1 (DL-193), 2026-10-23.
