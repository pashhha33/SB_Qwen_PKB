# Интеграция: Obsidian Bases

## Что это и зачем нам

**Bases** — **базовый (core)** плагин Obsidian: входит в поставку, отдельная установка не нужна,
но пользователь может его отключить. Рисует заметки как таблицы, карточки, списки и канбан
по их свойствам (frontmatter). Описание — файл `.base` (обычный YAML) или код-блок ` ```base `
внутри заметки.

Для Second Brain Bases — основной механизм представлений **В1–В6 и В11** (таблицы и карточки книг,
полка прочитанного, список глав, таблица людей, канбан проектов, проблемные объекты):
плагин **генерирует** `.base`-файлы в папку `Views/`, Obsidian их рисует. Собственный табличный
интерфейс мы не пишем.

## Что она умеет (факты, не догадки)

- Версия / дата проверки: документация help.obsidian.md, **проверено 2026-10-23** (страницы
  Introduction to Bases, Views, Bases syntax, Functions, Formulas). Ограничения карточного вида
  проверены при работе над `08-views.md` (2026-10-22).
- Есть ли публичный API: **специального API для плагинов нет**; интерфейс — **формат файла** `.base`
  (документированная YAML-схема). API настроек видов для авторов плагинов объявлен в документации
  как **будущее**.
- Что именно доступно (по документации):
  - Виды: `type` выбирается из встроенных — документированы и приведены в примерах `table`, `cards`,
    `list`, `kanban`, `map`; у вида — `name`, `limit`, `order`, `filters`, `groupBy` (с `direction`),
    `groupOrder` (значение `null` включает файлы без заполненного свойства), `summaries`.
  - Фильтры: глобальные (`filters`) и видовые (складываются через `AND`); `and` / `or` / `not`;
    сравнения; функции. **`from`/`source` нет — база всегда «всё хранилище»**, сужается только
    фильтрами (важно для генерации: всегда включать фильтр по `type`).
  - Функции: встроенные, по типам значений (Any, Date, String, Number, List, Link, File, Object,
    Regex) и глобальные (`date()`, `duration()`, `file()`, `html()`, `if()`, `escapeHTML()` и др.);
    поведение следует JavaScript.
  - Свойства: `note.*` (frontmatter), `file.*` (`name`, `path`, `folder`, `ext`, `size`, `ctime`,
    `mtime`, `tags`, `links`, `embeds`, `backlinks`, `properties`), `formula.*`.
  - `properties.*.displayName` — человекочитаемые (в том числе русские) названия колонок;
    **в фильтрах и формулах не используются** — там всегда ключи. Прямая совместимость с ADR-003
    (ключи английские, подписи русские).
  - `summaries`: стандартные формулы Average, Min, Max, Sum, Range, **Median**, Stddev, Earliest,
    Latest, Checked, Unchecked, Empty, Filled, Unique + свои через `values.*`.
    (Закрывает пометку `08-views` §11.5: медиана доступна штатно.)
  - Канбан — штатно: пример документации — `type: kanban` + `groupBy` + `groupOrder` (основа В6, DL-176).
- Свои функции и свои виды **от плагинов**: формулировки документации расходятся — страница фильтров
  говорит «plugins can add additional functions», страница формул — «в будущем плагины смогут
  добавлять функции», API настроек видов — будущее. **Не опора и не наша задача**:
  `bases-custom-functions`, `bases-custom-views` — в «не реализуем» (`09-modules.md` §6).
- Свойство-изображение карточного вида принимает вложение, URL или hex-цвет — **ссылку на заметку
  не принимает**; формула `image()` в карточках ненадёжна (проверено 2026-10-22, `08-views.md` §6.2).
  Отсюда теневое свойство `cover_file` (DL-144, DL-153).
- Источники: <https://obsidian.md/help/bases>, <https://obsidian.md/help/bases/syntax>,
  <https://obsidian.md/help/bases/views>, <https://obsidian.md/help/bases/functions>,
  <https://obsidian.md/help/formulas>.

## Варианты

### Вариант 1 — использовать как есть (генерировать `.base`-файлы)
- Плюсы: базовый плагин — нет сторонней зависимости; декларативный формат — можно генерировать
  и проверять; готовые таблицы, карточки, канбан, списки; `displayName` даёт русские подписи;
  7 представлений из 12 получаются «бесплатно».
- Минусы: реифицированные связи (`.sb/relations/*.jsonl`) Bases не видит; ограничения
  свойства-изображения; формат молодой — схема может уточняться от версии к версии.
- Риски: пользователь отключит базовый плагин; ручные правки сгенерированных файлов.

### Вариант 2 — реализовать таблицы самим
- Плюсы: полный контроль; можно показать связи из `.sb/`.
- Минусы: огромный объём UI-работы для новичка; результат хуже готового Bases; дублирование функции.
- Риски: затягивание разработки, раздувание этапа D.

### Вариант 3 — отказаться
- Плюсы: плагин проще.
- Минусы: все 12 представлений пришлось бы строить как `plugin_view` — против принятого `08-views.md`.

## Оценка

| Критерий | Оценка | Комментарий |
|---|---|---|
| Полезность для задач пользователя | Высокая | 7 из 12 представлений MVP (В1–В6, В11) |
| Совместимость с нашей метамоделью | Высокая | Читает обычный frontmatter; `displayName` — русские подписи; фильтры по ключам (ADR-003) |
| Стабильность API | Средняя | Базовый плагин с документацией, но молодой: схема `.base` может уточняться; защита — проверка версии в адаптере |
| Зависимость от чужого плагина | Низкая | Базовый, в поставке; можно лишь отключить вручную → пути деградации |
| Сложность реализации для новичка | Низкая | Пишем только генерацию и проверку YAML (`base-generator`), без встраивания в чужой UI |

## Риск и способ защиты метамодели

| Риск | Вероятность | Последствие | Мера защиты |
|---|---|---|---|
| Bases отключён или недоступен в старой версии Obsidian | Низкая | Представления не открываются | `bases-adapter` проверяет доступность и версию; у каждого представления В1–В12 есть путь деградации (`08-views.md` §4); правило `view.mechanism.available` |
| Схема `.base` изменится в обновлении Obsidian | Средняя | Сгенерированные файлы перестанут открываться | Маркер `# sb-generated: v1`; перегенерация **всегда спрашивает** и показывает разницу (DL-170); проверка версии в адаптере |
| Обложка не показывается в карточном виде | Подтверждено документацией | В2 без обложек | Теневое свойство `cover_file` (DL-144, DL-153); правило `media.referrers.shadow_synced`; команда `sb-resync-media-shadows` |
| Пользователь правит frontmatter через таблицу Bases мимо наших контролов | Средняя | Некорректные данные | Та же политика, что для стандартной панели Properties: проверка после записи (уровень 6), `severity-policy.md`; система ничего не переписывает молча |
| Ручная правка сгенерированного `.base` | Средняя | Конфликт при перегенерации | Не перезаписываем молча: показываем разницу и спрашиваем (DL-170) |
| Ожидание «в Bases видны все связи» | Средняя | Непонимание у пользователя | Честная документация: Bases видит только `direct`-ссылки во frontmatter; для реифицированных — карточка объекта (В7) и блок «Связан с этим объектом» |

## Решение

**Использовать как есть.** Единственный декларативный табличный механизм, встроенный в Obsidian;
закрывает 7 из 12 представлений MVP без собственного UI. Подтверждено пользователем: промпт проекта
(DL-004), `08-views.md` (DL-164…DL-171), канбан В6 (DL-176). Карточка создана по итогам под-шага 8d,
партия 1 (DL-193), 2026-10-23.

Модули: `bases-adapter` (изоляция, проверка доступности и версии, деградация) и `base-generator`
(генерация в `Views/`, маркер, перегенерация с вопросом) — `09-modules.md`, этап D.
