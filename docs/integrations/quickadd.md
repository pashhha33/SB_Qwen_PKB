# Интеграция: QuickAdd

> [!important] Решение одной строкой
> **Отложен** (ответ пользователя «А», DL-194; карточка — DL-197): как зависимость — отклонён
> (DL-018: вне MVP); на **этапе 2** возможен сценарий «быстрый захват», где QuickAdd —
> альтернативная точка входа **без кода с нашей стороны**.

## Что это и зачем рассматривали

QuickAdd — сторонний плагин быстрых рабочих потоков: создание заметок из шаблонов, «захват» текста
в заметку без её открытия, макросы (цепочки шагов, включая пользовательские скрипты), меню-группы.
В спецификации v1.0 §13 и v1.0 §9 упоминался как возможный «механизм» создания объектов —
подтверждён пользователем не был (C-11), DL-018 вынес его за рамки MVP.

## Что он умеет (факты, не догадки)

- Версия / дата проверки: **2.32.1** (багфикс-релиз, ~13 дней до проверки; верифицирован в реестре
  2026-10-10); **проверено 2026-10-23** (obsidianstats.com/plugins/quickadd,
  github.com/chhoumann/quickadd: 2 383 звезды, ~2,26 млн загрузок, 5 открытых issues —
  проект **очень активен**).
- Есть ли публичный API: да — форматный синтаксис, CLI-запуск (`quickadd-run`, опция `current=`),
  `quickAddApi` для пользовательских скриптов в макросах. Мы его не используем в MVP.
- Что именно доступно (по документации):
  - четыре вида «выборов» (choices): **Template** (создать заметку из шаблона с именем/папкой/
    свойствами), **Capture** (добавить текст в заметку, не открывая её), **Macro** (цепочка шагов:
    другие выборы, команды Obsidian, скрипты, AI-подсказки), **Multi** (папка в меню);
  - плейсхолдеры формата: `{{DATE}}`, `{{VALUE}}` (спросить текст), `{{FIELD:project}}`
    (подсказка значений из заметок), `{{LINKCURRENT}}`, буфер обмена и др.;
  - сценарий, релевантный нам: **Capture в «inbox»-заметку** — быстрый сброс мысли одним нажатием.
- Источники: <https://github.com/chhoumann/quickadd>, <https://quickadd.obsidian.guide/>.

## Варианты

### Вариант 1 — использовать как механизм создания объектов (из спецификации v1.0)
- Плюсы: готовые диалоги и шаблоны.
- Минусы: QuickAdd не знает нашей схемы — не построит `{TYPE_PREFIX}-{ULID}.md`, не заполнит
  системные атрибуты, не проверит `target_types`; конфликт с ADR-004 (создание только нашими
  командами) и с разделом 12 (перехват `vault.on('create')`, принцип «никогда не создавать молча»).
  **Отклонён** (DL-018).

### Вариант 2 — не использовать вовсе
- Плюсы: минус одна сущность в голове.
- Минусы: плагин активен и популярен; у пользователя он может стоять для своих задач —
  сосуществование всё равно нужно документировать.

### Вариант 3 — отложить: «быстрый захват» этапа 2 (принят)
- На этапе 2 планируется сценарий: быстро сбросить текст «в входящие», позже разобрать в объекты.
  Два возможных воплощения (выбор на этапе 2):
  1. **Своя команда** `sb-quick-capture` — без чужих плагинов (соответствует принципу П7 раздела 12);
  2. **Пользовательский Capture-выбор QuickAdd** в файл-входящие (например, `Inbox.md`) — точка входа
     без нашего кода; разбор входящих — наша команда/представление этапа 2.
- В обоих случаях QuickAdd остаётся **пользовательским** инструментом: мы его не вызываем
  и не зависим от него.

## Оценка

| Критерий | Оценка | Комментарий |
|---|---|---|
| Полезность для задач пользователя | Средняя (этап 2) | «Быстрый захват» — реальная потребность PKB; в MVP закрыт командами создания и перехватом пустых ссылок |
| Совместимость с нашей метамоделью | Низкая как механизм создания | Не знает схемы, ULID, системных атрибутов |
| Стабильность API | Высокая | Очень активный проект (2.32.1, релизы еженедельно) |
| Зависимость от чужого плагина | Отсутствует в принятом варианте | Точка входа — пользовательская настройка, не наш код |
| Сложность реализации для новичка | Нулевая в MVP | В MVP ничего не реализуем |

## Риск и способ защиты метамодели

| Риск | Вероятность | Последствие | Мера защиты |
|---|---|---|---|
| Template-выбор QuickAdd создаёт файл с произвольным именем и frontmatter | Средняя (если пользователь так настроил) | Файл вне схемы | Наш перехват создания из пустой ссылки его **не трогает**: принцип П4 раздела 12 — файл с содержимым остаётся обычной заметкой; создание объекта только явным действием |
| Capture пишет в заметку-объект текст, ломающий инварианты (например, тело `media`) | Низкая | Диагностика | Валидация уровней 2/4/6; инвариант И8; система ничего не переписывает молча |
| Плейсхолдеры `{{FIELD:…}}` предлагают значения вне нашей схемы | Низкая | Путаница у пользователя | Документируем: управляемый ввод — через наши команды и контролы |
| Ожидание «QuickAdd создаёт объекты Second Brain» | Средняя | Претензии | Честная документация границ (M6 ADR-001 по духу): объекты создаются только командами плагина (ADR-004) |

## Решение

**Отложить (deferred).** В MVP не используем и не интегрируем (DL-018): создание объектов —
только наши команды и перехват пустых ссылок (раздел 12). На этапе 2 сценарий «быстрый захват»
получит либо собственную команду `sb-quick-capture`, либо пользовательскую настройку QuickAdd
как точку входа — решение будет принято на этапе 2 по фактическим данным. Статус выбран
пользователем (ответ «А» на вопрос 8d, DL-194) вместо окончательного отказа: плагин активен,
сценарий захвата реален, зависимость при этом не возникает. Карточка создана в партии 2
шага 8d (DL-197), 2026-10-23.
