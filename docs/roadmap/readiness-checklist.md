## B. Правила и ограничения

- [x] B1. Реестр правил валидации (**167 правил**, v0.11.0, 14 групп A–N): у каждого правила есть ID, формулировка, уровень (`error`/`warning`/`info`)
      → [[../validation/rules|rules.md]]: **87 правил** в 8 группах (72 / 12 / 3), разметка по уровням контроля, таблица перекрывающихся правил. Закрыто 2026-10-22
- [x] B2. Политика уровней: что считать ошибкой, а что предупреждением, как это показывать пользователю
      → [[../validation/severity-policy|severity-policy.md]]: поведение по способу ввода, 6 уровней контроля, формат диагностики из 11 полей, 7 мест показа, 5 настроек. Закрыто 2026-10-22
- [x] B3. Определено, что плагин делает при неверных данных: только сообщает / предлагает исправление / исправляет
      → принцип зафиксирован в [[../validation/severity-policy|severity-policy.md]] §2 («не молча переписывать») и **четырьмя** исключениями §2.3; отмечено закрытым по содержанию (DL-200), формальная UX-проверка — на Фазе 5
- [x] B4. Потребность в миграциях зафиксирована, даже если сами миграции в MVP не реализуем
      → `docs/metamodel/10-migration-rules.md` *(v0.2.0, **accepted** — ответы А/А/А/А, DL-201…DL-205: принципы МГ1–МГ8, формат записи `.sb/migrations/`, версия схемы `.sb/state.json`, журнал, четыре образца; движок — этап 2). Закрыто 2026-10-23 → **блок B — 4/4 (100%)***
