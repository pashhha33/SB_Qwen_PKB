# Чек-лист готовности к реализации

> [!important] Как пользоваться
> Это «предполётный чек-лист». Пункт считается выполненным только если есть **файл-артефакт**,
> а не договорённость в переписке. В колонке «Артефакт» указывается путь.

## A. Ядро метамодели (обязательно для перехода к коду)

- [x] A1. Классификация типов согласована: три уровня `taxonomy → facet → category`, два теста «подтип или категория», границы `tags` и `categories`
      → [[../metamodel/01-classification|01-classification.md]], [[../adr/ADR-005-classification-model|ADR-005]]. Закрыто 2026-10-22
- [ ] A2. Список сущностей зафиксирован, для каждой есть отдельный файл по шаблону *(реестр готов; карточек ядра **3 из 15**: `book`, `person`, `chapter`)*
      → [[../metamodel/02-entities|реестр из 60 типов создан]], карточки `entities/*.md` — 0 из 11
- [ ] A3. Для каждой сущности определены: назначение, признаки типа, минимум 2 контрпримера *(форма утверждена DL-113; выполнено для 3 карточек)*
- [x] A4. Атрибуты описаны: тип значения, обязательность, допустимые значения, значение по умолчанию
      → [[../metamodel/04-attributes|04-attributes.md]] §2–§5, [[../adr/ADR-006-system-attributes-value-types-media|ADR-006]]. Закрыто 2026-10-22. Детализация по типам — в карточках сущностей
- [x] A5. Связи описаны: роли с обеих сторон, двусторонняя кардинальность, физическое хранение, поведение при ошибке
      → [[../metamodel/03-relations|03-relations.md]], [[../adr/ADR-009-relations-model|ADR-009]], [[../adr/ADR-010-relation-storage|ADR-010]], 4 карточки в `relations/`. Закрыто 2026-10-22
- [x] A6. Все enum-ы и справочники выписаны, значения в едином стиле
      → [[../metamodel/05-enumerations|05-enumerations.md]]: 15 перечислений, 13 закрытых. Закрыто 2026-10-22. Два перечисления (механизмы представлений и автоматизаций) утверждаются на шаге 8
- [x] A7. Правила для дат и интервалов зафиксированы: формат, обязательность, проверки порядка
      → [[../metamodel/06-time-and-intervals|06-time-and-intervals.md]]: частичные даты, интервалы, редактируемый шаблон вывода, системные даты, 11 правил. Закрыто 2026-10-22
- [ ] A8. Наследование и абстрактные типы либо описаны, либо явно отключены решением
      → признак `abstract` введён ADR-005, правила наследования перенесены в [[../metamodel/01-classification|01-classification]] §5; отдельный `07-hierarchy.md` не создан
- [ ] A9. Противоречия и дубли из черновиков пользователя разрешены; каждое разрешение зафиксировано
      → таблица в `docs/metamodel/01-classification.md` + ADR
- [x] A10. Именование идентификаторов утверждено единым соглашением
      → [[../adr/ADR-003-bilingual-keys-and-label-layer|ADR-003]], §«Соглашение об именах», DL-010. Закрыто 2026-10-22

## B. Правила и ограничения

- [x] B1. Реестр правил валидации (**102 правила**, v0.2.0): у каждого правила есть ID, формулировка, уровень (`error`/`warning`/`info`)
      → [[../validation/rules|rules.md]]: **87 правил** в 8 группах (72 / 12 / 3), разметка по уровням контроля, таблица перекрывающихся правил. Закрыто 2026-10-22
- [x] B2. Политика уровней: что считать ошибкой, а что предупреждением, как это показывать пользователю
      → [[../validation/severity-policy|severity-policy.md]]: поведение по способу ввода, 6 уровней контроля, формат диагностики из 11 полей, 7 мест показа, 5 настроек. Закрыто 2026-10-22
- [ ] B3. Определено, что плагин делает при неверных данных: только сообщает / предлагает исправление / исправляет
      → принцип зафиксирован в [[../validation/severity-policy|severity-policy.md]] §2 («не молча переписывать») и три исключения; формально пункт закрывается на Фазе 5 вместе с UX
