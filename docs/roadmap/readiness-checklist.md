# Чек-лист готовности к реализации

> [!important] Как пользоваться
> Это «предполётный чек-лист». Пункт считается выполненным только если есть **файл-артефакт**,
> а не договорённость в переписке. В колонке «Артефакт» указывается путь.

## A. Ядро метамодели (обязательно для перехода к коду)

- [ ] A1. Классификация типов согласована: группы, границы, критерий отличия одной группы от другой
      → `docs/metamodel/01-classification.md`
- [ ] A2. Список сущностей зафиксирован, для каждой есть отдельный файл по шаблону
      → `docs/metamodel/entities/*.md`
- [ ] A3. Для каждой сущности определены: назначение, признаки типа, минимум 2 контрпримера
- [ ] A4. Атрибуты описаны: тип значения, обязательность, допустимые значения, значение по умолчанию
      → `docs/metamodel/04-attributes.md` + файлы сущностей
- [ ] A5. Связи описаны: роли с обеих сторон, кардинальность, физическое хранение, поведение при ошибке
      → `docs/metamodel/relations/*.md`
- [ ] A6. Все enum-ы и справочники выписаны, значения в едином стиле
      → `docs/metamodel/05-enumerations.md`
- [ ] A7. Правила для дат и интервалов зафиксированы: формат, обязательность, проверки порядка
      → `docs/metamodel/06-time-and-intervals.md`
- [ ] A8. Наследование и абстрактные типы либо описаны, либо явно отключены решением
      → `docs/metamodel/07-hierarchy.md` + ADR
- [ ] A9. Противоречия и дубли из черновиков пользователя разрешены; каждое разрешение зафиксировано
      → таблица в `docs/metamodel/01-classification.md` + ADR
- [ ] A10. Именование идентификаторов утверждено единым соглашением
      → `docs/README.md#соглашение-об-именах` + DL-010

## B. Правила и ограничения

- [ ] B1. Реестр правил валидации: у каждого правила есть ID, формулировка, уровень (`error`/`warning`/`info`)
      → `docs/validation/rules.md`
- [ ] B2. Политика уровней: что считать ошибкой, а что предупреждением, как это показывать пользователю
      → `docs/validation/severity-policy.md`
- [ ] B3. Определено, что плагин делает при неверных данных: только сообщает / предлагает исправление / исправляет
- [ ] B4. Потребность в миграциях зафиксирована, даже если сами миграции в MVP не реализуем
      → `docs/metamodel/10-migration-rules.md`

## C. Представления и модули

- [ ] C1. Перечислены нужные представления: граф, таблицы, карточки, канбан, запросы — с приоритетами
      → `docs/metamodel/08-views.md`
- [ ] C2. Модули размечены: `реализуемый в MVP` / `отложен` / `нереализуемый`, каждый с обоснованием
      → `docs/metamodel/09-modules.md`
- [ ] C3. Разбиение на этапы готово, у каждого этапа есть критерий готовности
      → `docs/roadmap/phases.md`
- [ ] C4. Границы MVP записаны явно: что входит и что точно не входит
      → `docs/roadmap/mvp-scope.md`
- [ ] C5. Интеграции оценены: Bases, Templater, Dataview и прочие — решение по каждой + способ защиты метамодели
      → `docs/integrations/*.md`

## D. Машиночитаемые артефакты

- [ ] D1. JSON Schema создана для каждой сущности MVP и для самой метамодели
      → `schema/metamodel.schema.json`, `schema/entities/*.schema.json`
- [ ] D2. TypeScript-типы соответствуют JSON Schema (без расхождений)
      → `src/types/*` (или черновик в `schema/`)
- [ ] D3. Минимум 3 примера корректных экземпляров на каждый тип MVP
      → `examples/instances/*`
- [ ] D4. Минимум 2 примера **некорректных** экземпляров с указанием, какое правило они нарушают
      → `examples/instances/invalid/*`
- [ ] D5. Шаблоны заметок для создания новых экземпляров
      → `examples/templates/*`

## E. Учёт решений

- [ ] E1. Changelog ведётся, версия метамодели присвоена
- [ ] E2. ADR есть по каждому решению, влияющему на ядро
- [ ] E3. Decision log заполнен, нет записей в статусе `предложено` по критичным вопросам
- [ ] E4. Глоссарий проверен: нет дублей, противоречий и необъяснённых терминов
- [ ] E5. Карта проекта актуальна: фаза, решено, открыто, риски
      → `docs/project-map/PROJECT_MAP.md`

## F. Явное подтверждение

- [ ] F1. Пользователь письменно подтвердил: «Метамодель утверждена, переходим к реализации»
- [ ] F2. Версия метамодели поднята до `1.0.0`
- [ ] F3. Дата утверждения внесена в changelog и в карту проекта
