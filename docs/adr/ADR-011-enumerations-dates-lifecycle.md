# ADR-011. Перечисления, даты, интервалы и шаблон вывода

## Контекст

Шаг 7 плана. Открытыми оставались:

- **G-03**: значения перечислений разбросаны по черновикам и написаны в разном стиле — `строго`,
  `полиaрхическая` (с латинской «a»), `ручной`, `Base`, `QuickAdd`, роли изображений по-русски;
- **G-04**: формат дат зафиксирован в ADR-006, но неполные даты («1928 год, день неизвестен»)
  и интервалы не описаны;
- **U-07**: жизненный цикл `экспериментальное → стандартное → устаревшее → архивное` назван в `01` §16,
  но не сказано, что он меняет в поведении;
- **U-08**: шесть уровней контроля целостности из `01` §19 названы без определений.

Дополнительное предложение пользователя: «может, в настройках добавить редактируемый шаблон вывода
даты и времени».

## Проблема

1. В каком стиле писать значения перечислений?
2. Как хранить неполные даты и как их сравнивать?
3. Что реально меняет `lifecycle`?
4. Как задавать формат показа дат — фиксированным списком или редактируемым шаблоном?

## Рассмотренные варианты

### По стилю значений перечислений

| Вариант | Вид значения | Плюсы | Минусы |
|---|---|---|---|
| **A** | Английский `snake_case` в данных + русская подпись через справочник | Согласовано с ADR-003; нет смешения алфавитов; значения легко проверять | В режиме источника видно английское значение |
| B | Русский в нижнем регистре без пробелов | Читается сразу | Смешение алфавитов — источник опечаток `CHARACTЕR` и `полиaрхическая` |
| C | Русский с пробелами и заглавной | Красиво выглядит | Хрупко: лишний пробел или регистр ломают сравнение |

### По неполным датам

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| A | Только полные даты; неполные — текстом в `description` | Простая валидация | Потеря данных: нельзя отсортировать и отфильтровать по году |
| **B** | Неизвестная часть обозначается `00`: `1928-00-00` = только год | Данные машиночитаемы; сортировка и фильтр работают | `00` в дате выглядит непривычно; не является стандартом ISO 8601 |
| C | Отдельное поле `date_precision`: `year` / `month` / `day` | Явно и понятно | Два поля вместо одного; риск рассогласования |

### По шаблону вывода даты

| Вариант | Суть | Плюсы | Минусы |
|---|---|---|---|
| A | Фиксированный список из четырёх форматов на выбор | Просто реализовать | Не покрывает все вкусы; пользователь просил редактируемый |
| **B** | **Редактируемый шаблон из токенов** + несколько пресетов | Гибко; один механизм для даты, времени и частичных дат; совпадает с практикой Metadata Menu, который использует токены moment.js | Нужно реализовать разбор шаблона и валидацию неизвестных токенов |
| C | Полностью свободный шаблон без проверки | Максимальная свобода | Опечатка в токене даст мусор на экране без объяснения |

## Решение

Приняты варианты **A** (стиль перечислений), **B** (частичные даты), **B** (редактируемый шаблон вывода).

Формулировки пользователя: «1. A», «2. B, может в настройках добавить редактируемый шаблон вывода даты
и времени», «3. Согласен».

### Нормативная часть 1. Стиль значений перечислений

| Что | Норма | Пример |
|---|---|---|
| Значение в данных | английский `snake_case`, только строчные латинские буквы, цифры и подчёркивание | `strict`, `polyhierarchical`, `in_progress` |
| Подпись для интерфейса | русский текст, хранится отдельно | «Строгая», «Полиерархическая», «В работе» |
| Проверка формата | `^[a-z][a-z0-9_]*$` | правило `enum.value.format`, уровень `error` |
| Запрет | смешение кириллицы и латиницы, пробелы, регистрозависимые различия как единственный способ отличить значения | — |

**Где живут подписи значений.** Два способа, и они применяются по-разному:

| Способ | Когда | Как |
|---|---|---|
| Реестр в `05-enumerations.md` + таблица в коде плагина | Для **закрытых** технических перечислений: `value_type`, `cardinality`, `direction`, `hierarchy_mode`, `lifecycle` и т. п. | Пара `key` → `label` описана один раз |
| Категории фасета | Для **открытых** справочников, которые пополняет пользователь | Обычный механизм ADR-006: `value_type: object_reference` + `target_facet` |

Правило выбора остаётся из ADR-006: значений меньше десятка и они меняются только вместе с метамоделью →
перечисление; значений много и их пополняет пользователь → категория фасета.

### Нормативная часть 2. Частичные даты

| Запись | Что значит |
|---|---|
| `1928-00-00` | Известен только год |
| `1928-05-00` | Известны год и месяц |
| `1928-05-15` | Полная дата |

Правила:

- П1. Неизвестная часть обозначается `00` и **не может идти после известной**: `1928-00-15` недопустимо.
  Правило `date.partial.no_gap`, уровень `error`.
- П2. Значение `0000-00-00` означает «дата неизвестна» и допустимо там, где поле необязательно,
  но предпочтительнее оставить поле пустым.
- П3. **Сравнение.** Неизвестный компонент считается **меньше** любого известного. При сортировке
  по возрастанию `1928-00-00` идёт раньше `1928-05-00`, а та — раньше `1928-05-15`.
- П4. **Фильтрация.** При проверке «входит ли дата в диапазон» частичная дата входит, если входит
  хотя бы один день из ею описываемого множества. То есть `1928-00-00` попадает в диапазон «1928 год».
- П5. **Отображение.** Частичная дата показывается по своему шаблону (см. часть 4), а не с нулями:
  `1928-00-00` → «1928», `1928-05-00` → «май 1928».
- П6. Формат не является стандартом ISO 8601, поэтому значение **нельзя передавать внешним библиотекам
  разбора дат без нормализации**. Плагин нормализует частичную дату в диапазон перед любыми вычислениями.

### Нормативная часть 3. Интервалы

| Случай | Как записывается |
|---|---|
| Закрытый интервал | `starts_on: 1928-05-00`, `ends_on: 1929-00-00` |
| Открытый интервал («по настоящее время») | `ends_on: null` |
| Дата без интервала | одно поле типа `date` или `datetime` |
| Интервал с неизвестными концами | `starts_on: 1928-00-00`, `ends_on: null` — допустимо |

Правила:

- И1. `starts_on` не позже `ends_on` с учётом правила П3. Нарушение — `error`
  (правило `relation.period.order`, `object.period.order`).
- И2. `ends_on: null` означает «по настоящее время» — это **нормально**, а не ошибка. Уровень `info`.
- И3. Пересечение интервалов у связей одного типа от одного субъекта не запрещено по умолчанию.
  Если для конкретного типа отношения нужна непересекаемость, это объявляется отдельным полем
  `forbid_overlap: true` — **предложение, требует подтверждения**.
- И4. Длительность не хранится, а вычисляется.

### Нормативная часть 4. Редактируемый шаблон вывода

Шаблон — строка с **токенами** в квадратных скобках. Токен заменяется на значение при показе.

**Настройки плагина:**

| Настройка | Что задаёт | По умолчанию |
|---|---|---|
| `date_template` | Шаблон полной даты | `[DD].[MM].[YYYY]` |
| `datetime_template` | Шаблон даты со временем | `[DD].[MM].[YYYY] [HH]:[mm]` |
| `time_template` | Шаблон времени | `[HH]:[mm]` |
| `partial_year_template` | Шаблон даты с известным только годом | `[YYYY]` |
| `partial_month_template` | Шаблон даты с известными годом и месяцем | `[MMMM] [YYYY]` |
| `use_relative_dates` | Показывать ли «сегодня», «вчера», «N дней назад» | `false` |
| `relative_threshold_days` | Порог в днях для относительных дат | `7` |
| `relative_templates` | Шаблоны относительных дат | см. пресет ниже |

**Токены:**

| Токен | Что подставляет | Пример для 5 мая 1928 |
|---|---|---|
| `[YYYY]` | Год, четыре цифры | `1928` |
| `[YY]` | Год, две цифры | `28` |
| `[MM]` | Месяц, две цифры | `05` |
| `[M]` | Месяц без ведущего нуля | `5` |
| `[MMMM]` | Месяц словом в именительном падеже | `май` |
| `[MMM]` | Месяц сокращённо | `мая` |
| `[DD]` | День, две цифры | `05` |
| `[D]` | День без ведущего нуля | `5` |
| `[Do]` | День с русским окончанием | `5-е` |
| `[WW]` | ISO-номер недели | `18` |
| `[HH]` | Часы, 24-часовой формат | `14` |
| `[hh]` | Часы, 12-часовой формат | `02` |
| `[mm]` | Минуты | `35` |
| `[A]` | Половина дня словами | `дня` |
| `[ddd]` | День недели сокращённо | `сб` |
| `[dddd]` | День недели полностью | `суббота` |

Любой текст **вне** квадратных скобок выводится как есть. Пример: `[D] [MMMM] [YYYY] года` → `5 мая 1928 года`.

**Пресеты** (выбираются одной кнопкой, потом можно править):

| Пресет | `date_template` | `datetime_template` |
|---|---|---|
| Русская дата (по умолчанию) | `[DD].[MM].[YYYY]` | `[DD].[MM].[YYYY] [HH]:[mm]` |
| ISO | `[YYYY]-[MM]-[DD]` | `[YYYY]-[MM]-[DD]T[HH]:[mm]` |
| Словесная | `[D] [MMMM] [YYYY]` | `[D] [MMMM] [YYYY], [HH]:[mm]` |
| Короткая | `[DD].[MM].[YY]` | `[DD].[MM].[YY] [HH]:[mm]` |
| Американская | `[MM]/[DD]/[YYYY]` | `[MM]/[DD]/[YYYY] [hh]:[mm] [A]` |

**Пресет относительных дат** (применяется, когда `use_relative_dates: true` и дата в пределах порога):

| Случай | Шаблон | Пример |
|---|---|---|
| Сегодня | `сегодня, [HH]:[mm]` | `сегодня, 14:35` |
| Вчера | `вчера, [HH]:[mm]` | `вчера, 19:02` |
| Завтра | `завтра, [HH]:[mm]` | `завтра, 10:00` |
| N дней назад | `[N] дн. назад` | `3 дн. назад` |
| Через N дней | `через [N] дн.` | `через 5 дн.` |
| Вне порога | обычный `date_template` | `12.03.2026` |

**Правила поведения шаблона:**

- Ш1. Неизвестный токен показывается как есть, в квадратных скобках, и даёт `warning` в настройках:
  «неизвестный токен `[XYZ]`». Никакого молчаливого мусора.
- Ш2. Шаблон применяется **только к отображению**. В файлах всегда канонический формат.
- Ш3. Один и тот же шаблон действует во всех наших представлениях: модалка свойств, таблицы, карточки,
  блок связей, диагностика. В стандартной панели свойств Obsidian формат не подменяется.
- Ш4. Шаблон проверяется при сохранении настройки: пустая строка и строка без токенов допустимы
  (выведется как есть), неизвестный токен — предупреждение.
- Ш5. Частичные даты используют свои шаблоны (`partial_year_template`, `partial_month_template`),
  а не основной `date_template`.

### Нормативная часть 5. Поведение `lifecycle`

Значения и их влияние:

| Значение | Подпись | Что делает плагин |
|---|---|---|
| `experimental` | Экспериментальное | Значения принимаются; при валидации выдаётся `info`: «свойство экспериментальное, может измениться» |
| `standard` | Стандартное | Обычное поведение. **Значение по умолчанию** |
| `deprecated` | Устаревшее | При валидации — `warning`: «свойство устарело, используйте …». Команды создания **не предлагают** это свойство. Существующие значения не ломаются |
| `archived` | Архивное | Свойство скрыто из форм и списков. Существующие значения сохраняются и читаются. Валидация не ругается |

Дополнительные правила:

- Ж1. У значения `deprecated` **обязательно** поле `superseded_by` — указание на замену.
  Правило `property.lifecycle.deprecated_has_replacement`, уровень `error`.
- Ж2. Переход `standard → deprecated → archived` — обычный путь. Обратный переход допустим,
  но требует явного действия пользователя.
- Ж3. Удаление определения свойства — не то же самое, что `archived`. Удаление запускает каскадные
  правила из Р12 ADR-009; `archived` не удаляет ничего.
- Ж4. `lifecycle` применяется к **свойствам и типам объектов**. К таксономиям, фасетам и категориям —
  на этапе 2, если понадобится.

### Нормативная часть 6. Шесть уровней контроля целостности

Спецификация v1.0 §19 называет шесть проверок без определений. Даю определения (закрывает U-08):

| Уровень | Что проверяет | Когда запускается | Пример правила | Уровень сообщения |
|---|---|---|---|---|
| 1. **Предварительная** | Данные, которые пользователь вводит прямо сейчас, до записи | В модалке при вводе | `value.type_conformance` | блокирует запись при `error` |
| 2. **Техническая** | Формат и идентичность: ULID, имя файла, кодировка, формат даты, наличие системных атрибутов | При чтении объекта и при записи | `object.id.format`, `object.id.filename_match`, `date.partial.no_gap` | `error` |
| 3. **Структурная** | Ссылки и связи: существование цели, допустимый тип цели, кардинальность, уникальность, отсутствие циклов | При чтении, при изменении, по команде | `value.reference.exists`, `relation.cardinality.subject_to_object`, `object_type.parent.no_cycle` | `error` / `warning` |
| 4. **Семантическая** | Соответствие правилам метамодели: обязательность, перечисления, согласованность наследования, `lifecycle`, согласованность подтипа и фасета | При изменении и по команде | `property.required.cardinality_consistency`, `source.media_facet.consistency`, `relation_type.symmetric.labels_equal` | `error` / `warning` / `info` |
| 5. **Проверка представлений** | Что представление можно построить: целевые типы существуют, нужные свойства объявлены, механизм доступен | При построении представления | `view.target_types.exist`, `view.properties.declared` | `warning` |
| 6. **Постпроверка** | Состояние после записи: объект сохранился корректно, индекс обновлён, каскадные действия выполнены | После записи | `object.saved.consistent`, `relation.cascade.completed` | `error` |

Правила запуска:

- Уровни 1 и 6 работают всегда, их нельзя отключить.
- Уровни 2–4 работают локально при изменении объекта и полностью — по команде `validate-vault`.
- Уровень 5 работает лениво, при открытии представления.
- Результат проверки — список диагностик: объект, поле, фактическое значение, нарушенное правило,
  возможный способ исправления.

## Обоснование

1. **Английские значения перечислений** устраняют источник опечаток, который уже проявился в черновиках
   дважды (`CHARACTЕR`, `полиaрхическая`). Подписи при этом русские — пользователь не теряет читаемости.
2. **Частичные даты через `00`** выбраны потому, что сохраняют данные машиночитаемыми: год можно
   отсортировать и отфильтровать. Альтернатива с текстом в `description` эти данные теряет.
3. **Редактируемый шаблон** — прямое выполнение предложения пользователя. Он же снимает будущие споры
   о формате: вместо изменения метамодели пользователь правит настройку. Пресеты снижают порог входа.
4. **`lifecycle` получил поведение** — иначе поле было бы описательной пометкой без смысла.
5. **Шесть уровней контроля** описаны в терминах «что проверяет / когда запускается», а не абстрактно.
   Это делает их реализуемыми и тестируемыми.

## Последствия

### Положительные
- Закрыты G-03, U-07, U-13; G-04 закрыт полностью; U-08 закрыт.
- Единый стиль значений по всей модели.
- Формат показа дат перестал быть предметом решений о метамодели — это настройка.
- Шесть уровней контроля из спецификации получили определения и стали реализуемыми.

### Отрицательные / чем платим
- Частичные даты с `00` — нестандартный формат. Нельзя отдавать внешним библиотекам без нормализации.
- Разбор шаблона вывода — это дополнительный код: токены, пресеты, проверка неизвестных токенов,
  русские названия месяцев и дней недели, относительные даты с русскими формами числительных
  («1 день», «2 дня», «5 дней»).
- `lifecycle` добавляет поведение в валидацию: четыре ветки вместо одной.

### Обязательные компенсирующие меры

| № | Мера |
|---|---|
| M1 | Русские формы числительных в относительных датах реализуются через отдельную функцию склонения, а не подбором шаблона |
| M2 | Неизвестный токен показывается как есть и даёт `warning` — никогда не молчаливый мусор |
| M3 | Разбор шаблона покрыт тестами: каждый токен, пустой шаблон, шаблон без токенов, неизвестный токен, вложенные скобки |
| M4 | Нормализация частичной даты в диапазон — отдельная функция с тестами, единственная точка входа для всех вычислений |
| M5 | Реестр перечислений в `05-enumerations.md` — единственный источник; код плагина сверяется с ним тестом |
| M6 | Пресеты дат не являются особым случаем в коде: это просто сохранённые строки шаблонов |

## Влияние на метамодель

| Что меняется | Было | Стало | Ломающее изменение? | Нужна миграция? |
|---|---|---|---|---|
| Значения перечислений | русский разнобой | английский `snake_case` + русская подпись | **да** | Да; данных нет |
| Частичные даты | не определены | `00` в неизвестных компонентах + правила П1–П6 | нет | нет |
| Интервалы | не определены | правила И1–И4; `ends_on: null` = открытый период | нет | нет |
| Формат показа дат | фиксированный список из ADR-006 | **редактируемый шаблон из токенов** + пресеты | уточнение | нет |
| `lifecycle` | описательное поле | четыре значения с разным поведением + обязательное `superseded_by` у `deprecated` | нет | нет |
| Шесть уровней контроля | названы без определений | определены: что проверяют, когда запускаются, какой уровень сообщения | нет | нет |

## Открытые следствия

1. **`forbid_overlap` у типа отношения** — предложение в правиле И3, требует подтверждения.
2. **Склонение русских слов** в относительных датах и названиях месяцев — техническая задача Фазы 5.
3. **Шаблоны в представлениях** (таблицы, карточки) — могут понадобиться отдельные шаблоны на представление.
   Отложено на шаг 8.
4. **`lifecycle` у категорий и фасетов** — отложено на этап 2.
5. **Правила отсутствия цикла** в цепочках «часть — целое» и в иерархии категорий — входят в уровень 3,
   конкретные формулировки в `docs/validation/rules.md`.
