# Second Brain

Метамодель личной базы знаний и плагин для [Obsidian](https://obsidian.md), который её поддерживает.

**Что это.** Не «список типов заметок», а самоопределяющаяся объектная модель: тип объекта, свойство,
тип свойства, тип отношения, отношение, таксономия, фасет, категория, представление и автоматизация —
тоже объекты со своими `id` и `type`. Модель расширяется без изменения кода плагина.

**Стадия проекта.** Метамодель версии `0.2.0` — зафиксирован фундамент (идентификация, хранение, имена
полей, объём первого прохода, классификация). Код плагина ещё не начинался.

## Главные правила проекта

| Правило | Где зафиксировано |
|---|---|
| Документация на русском, идентификаторы и код на английском | [[docs/adr/ADR-003-bilingual-keys-and-label-layer\|ADR-003]] |
| Локально и офлайн, без внешних API и LLM в MVP | промпт проекта, DL-002 |
| `id` объекта — голый ULID, имя файла `{TYPE_PREFIX}-{ULID}.md` | [[docs/adr/ADR-001-identity-and-file-naming\|ADR-001]] |
| Определения метамодели — Markdown-заметки в хранилище; `.sb/` — только служебные данные | [[docs/adr/ADR-002-source-of-truth\|ADR-002]] |
| Элементы метамодели создаются командами плагина, а не ручным редактированием | [[docs/adr/ADR-004-first-pass-scope-and-command-driven-authoring\|ADR-004]] |
| Классификация: `taxonomy → facet → category`, обязательность задаёт фасет | [[docs/adr/ADR-005-classification-model\|ADR-005]] |
| Система не должна молча переписывать неправильные данные | спецификация v1.0 §19, сохранено |
| Старые документы не удаляются, а помечаются `deprecated` / `superseded` | [[docs/README]] |

## Как вести документацию

Коротко (полностью — в [[docs/README]]):

1. Новое решение → артефакт **сразу**, в тот же ход.
2. Новые файлы создаём, старые не удаляем; устаревшему ставим `status` и `superseded_by`.
3. У каждого артефакта есть frontmatter: `doc_type`, `status`, `version`, `created`, `updated`.
4. Термины — в глоссарий сразу, в тексте даём ссылку, а не повторное объяснение.
5. Каждое изменение метамодели — запись в changelog с версией, причиной и ссылкой на ADR.
6. Контрольная точка обновляется после каждого сообщения с решениями.
