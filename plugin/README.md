## Бутстрап `Metamodel/` (A2 часть 2, DL-257)

Метамодель описывает саму себя, поэтому системные типы нужны до того, как их можно
прочитать из хранилища (главный риск этапа A, `phases.md` §4). Решение ADR-004:
определения поставляются внутри плагина как данные и выгружаются при первом запуске.

- **Объём семени — F5-10 = Б**: 7 OBJECT_TYPE-заметок. Определения свойств системных
  типов появятся в B1 вместе со schema-engine; предметная библиотека (`book`, `person`, …) —
  отдельной командой «установить основные типы» в B1. `property_type` не сеется:
  абстрактный, без карточки (ADR-004).
- **Фиксированные ULID — F5-9 = А**: `id` семенных заметок — системные константы,
  одинаковые во всех хранилищах. Рецепт воспроизводим (закреплён тестом): временная часть —
  дата утверждения метамодели 1.0.0 (2026-10-23T00:00:00Z), энтропия — первые 16 байт
  SHA-256 от строки `second-brain/system-type/{type_key}`. Исключение из правила
  «`id` не переиспользуется» зафиксировано примечанием в ADR-001 (ревизия 0.2.1).
- **Идемпотентность**: бутстрап проверяет существование файла и НЕ перезаписывает его —
  правки пользователя остаются в силе (источник истины — хранилище, ADR-002).
- **Отказоустойчивость**: ошибка записи одного семени не прерывает остальные;
  итоги — в Notice (только при изменениях/ошибках) и в журнале (`bootstrap`, info/debug).
- **Порядок в `main.ts`**: бутстрап → перечитывание реестра → Notice загрузки
  («типов в реестре: 7»).

## Генерация TS-типов из схем (D2, A3 — DL-258)

Типы **не пишутся руками** (конструкция DL-222): единственный источник истины — JSON Schema
в `schema/**` корня репозитория.

```powershell
npm run generate:types      # перегенерировать src/generated/ (13 файлов)
npm run check:types-fresh   # только сверка: «перегенерация == зафиксированное» (rc=1 при расхождении)
```

Сгенерированные файлы **коммитятся**; тест `tests/unit/generated-freshness.test.ts`
запускает `--check` на каждом `npm test` — забытая перегенерация не пройдёт. После правки
любой схемы: `npm run generate:types` → коммит обоих изменений вместе. Ограничение (честно,
M6): `if/then/else`-блоки схемы генератор уплощает — типы являются приближением; норма —
схема и рантайм-валидация плагина.

## Front Matter Title — необязательная интеграция (A3 — DL-258)

Уровень 2 читаемости ADR-001: сторонний плагин Front Matter Title показывает `title` из
frontmatter вместо имени файла (`BOOK-01J….md`) в проводнике, вкладках и поиске. Наш адаптер
(`src/core/front-matter-title.ts` + защитное обнаружение в `main.ts`) только **обнаруживает**
его и один раз рекомендует поставить, если его нет (флаг `fmtAdviceShown` в
`.sb/settings.json`); никакого управления чужим плагином (публичного API у него нет).
Сбой адаптера деградирует молча (М3); без FMT всё работает — показываются имена файлов (М4).

## Валидация по метамодели (B1.1 часть 1, DL-263)

`validate-object` проверяет заметку по реестру правил (`docs/validation/rules.md`):

- **группа A** — системные атрибуты и инварианты И1–И5 (этап A2);
- **группа B** — определения свойств (16 правил): формат/уникальность/системные конфликты
  ключа, подпись, закрытый набор `value_type` (7 типов), согласованность `required` и
  `cardinality`, `target_types` у ссылок, `target_facet` — только фасет, пять правил
  `applies_when` (М3/М4), `create_from_link: auto` при единственной цели, пара
  `object_types.*` (F5-8);
- **группы C/G** — значения экземпляров: соответствие типам значения, кардинальности
  (включая обязательность), ссылки (существование и допустимый тип цели — через индекс
  хранилища), перечисления (латиница, формат, вхождение в `allowed_values`);
- **группа H** — даты: форматы, частичные даты (`00`, правило П1 «без пробелов»),
  допустимость дня/месяца с високосными, секунды — предупреждение.

### Часть 2 (0.7.0, DL-266)

- **Условные свойства** (`applies-when`, М1–М7): свойство с `applies_when` проверяется
  на обязательность, только когда условие выполнено (М6); сохранённые значения «погасших»
  свойств не удаляются (М2) и продолжают проверяться на качество (тип, перечисление,
  ссылка, дата). Операции: `equals`, `includes_any` (мультивыбор), `in_category`
  (прямое назначение категории; предки категорий — B1.3).
- **Служебный слой диагностик** (`service-flags`, 08-views §7): после проверки плагин
  пишет в заметку служебные метки `sb/error` / `sb/warning` / `sb/info` (наивысшая
  серьёзность) и служебное свойство `sb_issues` (список «{rule_id}: {severity}») — строго
  парой; правила группы K ловят ручную правку (`diagnostics.service_property.readonly`),
  рассинхрон меток и свойства (`diagnostics.tags_issues_synced`) и отсутствие объявления
  (`diagnostics.service_property.declared`). Объявление `sb_issues` сеется бутстрапом
  (`Metamodel/Properties/PROPERTY-01M5K0XB00T6WT7SFWZBG4M9NB.md`) — не удаляйте его.
  Служебная запись не трогает `updated_at` и пишется только на объекты Second Brain
  (заметки с `id`/`type` во frontmatter).
- **Группа E** — определения типов (`object_type.*`): существование родителя, отсутствие
  циклов, уникальность `TYPE_PREFIX`, отсутствие экземпляров у абстрактного типа
  (последнее — в `validate-vault`: правило масштаба хранилища).
- **Правило П2** — `date.all_unknown.optional_only` (warning): дата `0000-00-00`
  допустима только в необязательном поле (rules.md v0.14.0 — 171 правило).
- **Команда `create-property`**: определение свойства командой (ADR-004) — vanilla-модалка;
  `required` выводится из `cardinality`; проверки уровня 1 зеркалят группу B — созданное
  определение проходит `validate-object` без диагностик.
- **Команда `validate-vault`**: проверка всего хранилища (уровни 2–4, 6) — один общий
  индекс на прогон, служебные метки обновляются, сводка (Notice + окно: итоги, топ-10
  проблемных заметок, vault-диагностики), одна запись в журнал.

Границы (честно, M6 — `docs/plugin/architecture.md` §5, B1.1-1…9): ссылки разрешаются по
каноническому имени и имени файла (псевдонимы — B2); `period.*` — этап C;
`display_template.*` и формы — B1.2; `target_facet`/`default_value`/`display.*` в
create-property не предлагаются (B1.2/B1.3); `abstract.no_instance` — только в validate-vault.

**Этап A закрыт** (все чек-боксы DoD, phases.md §4; чек-лист готовности — 32 из 32);
**под-батч B1.1 закрыт** обеими частями. Дальше — **B1.2** (формы и контролы, Svelte 5 +
`esbuild-svelte`), **B1.3** (классификация + «установить основные типы»: book и person),
B2 «ссылки и псевдонимы».

## Формы свойств (B1.2 часть 1, DL-268)

**Первое включение Svelte** (B1-2 = А): компонент `src/ui/svelte/property-editor.svelte`
(Svelte 5 runes) монтируется внутри оболочки `Modal` (DL-175) — `src/ui/property-editor-modal.ts`
(mount/unmount). Сборка — esbuild + `esbuild-svelte` (стили `css: 'injected'` — тот же
`main.js`; runtime-зависимостей ноль; dev-зависимости: `svelte`, `esbuild-svelte`,
`svelte-preprocess` — после переноса батча нужен `npm ci`).

- **Команда `edit-object`** — форма свойств активной заметки: русские подписи
  (LabelResolver; режим `source` показывает ключи), условные поля (`applies_when`)
  появляются и исчезают ЖИВЬЁМ при вводе триггера (М1), значения «погасших» полей
  сохраняются при записи (М2), ошибки формата под полями блокируют «Сохранить»
  (уровень 1 — ADR-011), сохранить неполный объект можно (DL-183 «сначала объект,
  потом поля»), множественные значения — строки с кнопками «+ добавить» / «×»,
  предпросмотр звёзд/прогресса для чисел с `display.*` (символы в данных не хранятся —
  DL-117/123), служебные свойства (`service: true`) в форму не попадают (08-views §7),
  **«Выбрать…» у ссылок** (0.9.0, DL-273: `LinkPickerModal` — поиск объектов по названию
  с фильтром `target_types`, вставка канонической ссылки `[[PREFIX-ULID.md|название]]`;
  у `media_target: file` подборщика нет — этап D), **быстрые кнопки дат** («Сегодня» /
  «Сейчас» / «Неизвестна» — `0000-00-00` только в необязательных полях, П2) и
  **переключатель подписей в форме** («русские/ключи», стартует глобальным режимом;
  глобальный toggle-label-mode применяется к вновь открываемым формам — граница B1.2-6).
- **Команда `toggle-label-mode`** — переключение подписей view/source (ADR-003),
  режим сохраняется в `.sb/settings.json`.
- **`create-object`** после создания сразу открывает форму (сбой формы не отменяет
  создание объекта).
- Ядро: `object-service` (модель формы, уровень 1, запись: `title` + И4-синхронизация
  `aliases[0]`, `updated_at`, неизвестные поля frontmatter сохраняются) и
  `display-renderer` (plain/stars/progress) — среда-независимы и покрыты тестами;
  TypeScript внутри `.svelte` не проверяется tsc — логика поэтому живёт в ядре
  (граница B1.2-2, architecture §5).

Границы формы (architecture §5): контрол ссылки — текстовое поле + подборщик «Выбрать…»
(псевдонимы в поиске не участвуют — B2; `media_target: file` — этап D, B1.2-7);
`categories`/`tags` в форме не редактируются (B1.3 / штатная панель Obsidian);
определения метамодели (типы/свойства) через форму не правятся — только команды
create-* (ADR-004); глобальный режим подписей не обновляет уже открытую форму —
внутри формы есть локальный переключатель (B1.2-6).

## Базовая библиотека (B1.3 часть 1, DL-277)

Команда **«Установить основные типы (book, person)»** (`install-base-types`, 22-я команда
реестра — DL-276) создаёт в `Metamodel/` определения предметной библиотеки:

- **OBJECT_TYPE** `book` (родитель `work`), `person` + структурные `work` (абстрактный,
  без свойств — DL-214) и `media` (цель ссылок `media_reference`; свойства — этап D,
  граница B1.3-5: этап D обязан использовать тот же фиксированный ULID);
- **FACET** `Genre`, `Literary form`, `Country`, `Language`, `Sport` — системные
  определения, на которые ссылаются словарные свойства (04-attributes §5). **Категории
  не создаются** (Ч3-3 = Б, DL-276): содержимое хранилища добавляет пользователь
  командой «Создать объект» (тип «Категория»);
- **PROPERTY** — 65 определений полей системных типов (долг F5-10 = Б; с 0.11.0 —
  плюс `label` у таксономии/фасета/категории, B1.3-6 = А), 22 свойства
  `book` (12 базовых + 10 условных по `format`) и 42 свойства `person` (15 базовых +
  27 условных по `role`, includes_any — М7).

Механизм (B1-4 = А, DL-261): сиды — статические данные плагина (`src/core/seeds/`),
фиксированные ULID по рецепту SHA-256 от `second-brain/system-{type|facet|property}/…`
(генератор `scripts/generate-seed-ulids.mjs`, файл `seed-ulids.ts` коммитится; тест
воспроизводит рецепт). Согласованность со схемами — тест `seed-consistency.test.ts`
(состав полей, enum-ы, обязательность, applies_when — «сиды == `schema/**`»).
**Идемпотентность — пропуск по ключу** (DL-276): существующие типы/свойства/фасеты
(созданные командами при проверках) не дублируются; ссылки сидов разрешаются в ULID
существующих определений. Установка чистого хранилища байт-стабильна (тест).

Границы части 1 — architecture §5 (B1.3-1…B1.3-6): PROPERTY-сиды `relation` — этап C;
`display`/`applies_when` как поля типа `property` не сеются (составные структуры);
enum-ы кардинальностей не объявляются `allowed_values` (enum.value.format);
`book.publisher` — этап 2 (тип `organization`); `cover_file`/`portrait_file` — этап D.

Проверка после переноса: `Ctrl+P` → «Установить основные типы (book, person)» → Notice
«создано N, пропущено M»; повторный запуск — «создано 0, пропущено …» (идемпотентность);
`validate-vault` — 0 ошибок.

## Классификация (B1.3 часть 2a, DL-278)

`classification-service` (ядро, `src/core/classification.ts`) строит **снимок**
классификации по заметкам `Metamodel/{Taxonomies,Facets,Categories}` (а также по
каноническим именам `TAXONOMY-`/`FACET-`/`CATEGORY-` в любом месте хранилища):

- **наследование умолчаний** — «значение фасета → значение таксономии → таблица
  `01-classification` §2.2» (`hierarchy_mode`, `assignment_cardinality`,
  `root_requirement_min/max`, `allowed_object_types`);
- **предки категории** — транзитивное замыкание по `parent` (цикл обрывается безопасно):
  условное свойство с `in_category` по предку срабатывает, когда назначен потомок
  (граница B1.1-4 закрыта; работает и в валидации, и в форме);
- **кэш** `.sb/cache/classification.json` — производные данные (ADR-002): пишет
  `validate-vault`, источник истины всегда заметки;
- **область чтения минимальна** (фикс 0.11.1, урок DL-255/259/281): только
  `Metamodel/{Taxonomies,Facets,Categories}` и канонические имена `TAXONOMY-`/`FACET-`/
  `CATEGORY-` где угодно — снимок дёшев (5–10 заметок), поэтому его можно строить на
  каждую проверку; в прогоне по всему хранилищу (`validate-vault`) снимок один на прогон.

Правила группы E (`src/core/classification-engine.ts`, 15 правил — `rules.md` §E):
определения (`category.facet.required/single`, `category.parent.exists/same_facet/`
`no_cycle/strict_mode`, `category.taxonomy_direct.forbidden` — П8, `facet.taxonomy.exists`,
`facet.allowed_types.conflict`, `facet.root_requirement`, `taxonomy.facets.min_one`) и
назначения (`assignment.type_allowed`, `assignment.cardinality`,
`facet.genre.required_for_book` — error, `facet.genre.not_form` — warning).
Специальные правила имеют приоритет над общими (rules.md «Перекрывающиеся правила»):
на полях классификации не дублируются `value.cardinality`, `value.reference.exists`,
`value.reference.target_type`.

> [!note] Что изменится в проверках после обновления
> - Книга без назначенного жанра даёт **error** `facet.genre.required_for_book`
>   (норма Ч3-3 = Б: категории создаёт пользователь).
> - Семенной фасет «Жанр» без корневых категорий даёт **warning** `facet.root_requirement`
>   (минимум 1 корень, DL-126) — уходит после создания первой корневой категории.

### Назначение категорий — команда `assign-category` (0.12.0, DL-283)

`Ctrl+P` → **«Назначить категорию (assign-category)»** на открытой заметке объекта:

1. **Фасет** — в списке только применимые к типу объекта (`allowed_object_types` фасета
   или таксономии; ссылка на предка включает потомков — DL-208/209);
2. **Категории** — списком сверху вниз, с отступами по иерархии (родитель раньше потомка);
   уже назначенные отмечены;
3. **Счётчик** — «Выбрано: N · кардинальность фасета: 1..N» с живой подсказкой;
4. **«Сохранить назначение»** — запись в системное поле `categories` каноническими
   ссылками `[[CATEGORY-{ULID}.md|title]]` + `updated_at` (И5) + запись в журнал.

Правила поведения (нормы ADR-011 и DL-183):

- **отказ уровня 1** (не сохраняется): категория принадлежит другому фасету; тип вне
  области применения фасета (`assignment.type_allowed`); **превышение** кардинальности
  (`1` и `0..1` — больше одной категории);
- **предупреждение, но сохраняется**: недобор (0 категорий при `1`/`1..N`) — неполный
  объект допустим, ошибку покажет `validate-object` (`facet.genre.required_for_book`);
- категории **других фасетов** и нераспознанные записи в `categories` сохраняются как были
  (авторский отображаемый текст ссылок не переписывается — DL-184);
- форма свойств `categories` не редактирует (граница B1.3-10) — назначение командой.

## Правила кода (кратко)

- Идентификаторы — английский `snake_case`/`camelCase` (ADR-003); комментарии и
  документация — русский.
- Ядро (`src/core/**`) не импортирует `obsidian` — только интерфейс `VaultAdapter`
  (правило М2, `09-modules` §3; проверяется тестом `tests/integration/layering.test.ts`).
- YAML разбирается только реализацией среды (`adapter.parseYaml`), не самописно (ADR-002).
- Пути строим через `node:path` / `pathToFileURL` — урок DL-232 (Windows, пробелы, кириллица).
- Каждый модуль с тестами (правило М4); интеграционные — на `FakeVault`
  (`tests/support/fake-vault.ts`), контракт-тесты — `tests/integration/adapter-contract.test.ts`.
- Семенные данные бутстрапа — статические строки: LF, без BOM, без токенов Templater
  (`<% %>`) — DL-190: плагин не пишет токенов, которые Templater мог бы раскрыть.
- Контракт `dataWrite` (DL-255): создаёт родительские папки — `DataAdapter.write` в Obsidian
  этого не делает сам; прод-адаптер строит цепочку `.sb/` по уровням перед записью
  (исключение из М4: юнит-тест `tests/unit/obsidian-adapter.test.ts` на стабе
  `tests/support/obsidian-stub.ts` — алиас `vitest.config.ts`).
